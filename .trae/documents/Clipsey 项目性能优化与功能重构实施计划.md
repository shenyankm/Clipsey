## 总览
- 目标：围绕性能优化与功能划分两大维度，落地一组改造以提升检索速度、页面渲染效率、内存稳定性，并降低模块耦合与重复实现。
- 范围：IndexedDB 查询/搜索层、内容脚本高亮定位与渲染、前端资源加载策略、后台生命周期与同步机制、目录与职责重组。

## 阶段一：搜索与数据访问层优化
1. 将关键字搜索迁移到 IndexedDB 游标/索引检索，移除“全量加载后内存过滤”。
2. 为 `clips` 建立/利用小写字段（如 `sourceUrlLower`、`titleLower`、`textContentLower`）或在查询前统一规范化，避免每次搜索进行重复 `toLowerCase()`。
3. 改造 `SearchService`：通过 `IndexedDBQuery` 的分页与索引能力直接返回数据；保留无关键字分页路径。
4. 为模糊搜索新增“流式匹配”选项：在游标迭代中做包含判断而非一次性 `getAll`。
5. 新增单元测试：覆盖空关键字、不同排序维度、超大数据集下性能基准。

## 阶段二：文本定位与高亮渲染性能优化
1. 将 `text-search.ts` 的“拼接整段字符串后匹配”改为基于 Text 节点的流式搜索算法（如增量 Boyer-Moore/KMP）。
2. 为超大页面引入可选 Web Worker：在 UI 线程之外执行文本搜索，主线程仅接收定位结果与渲染指令。
3. 统一片段收集与包裹逻辑：删除 `selection.ts` 中与 `painters.ts` 重复的实现，改为调用统一渲染器（保持行为一致）。
4. 在 `HighlightEngine` 中将固定休眠（150/200/300ms）改为 `requestIdleCallback` 或基于 DOM 就绪的自适应短延时。
5. 新增性能测试：页面 1w+ 文本节点下定位与渲染耗时对比。

## 阶段三：资源加载与滚动体验优化
1. 对“固定/粘性头部高度”测量结果做缓存，并在 `resize` 或必要的 DOM 变化时失效刷新，避免重复 `getBoundingClientRect/getComputedStyle`。
2. 弹窗/设置页按需加载组件：保持现有“选择性注册”，对体积大的组件或低频视图采用动态导入分包。
3. 保持内容脚本 `document_idle` + 动态导入策略，检查子模块是否存在可进一步拆分的边界（如复杂选择/渲染逻辑独立分包）。

## 阶段四：同步与生命周期内存安全
1. 在后台 `cleanupAll` 中合入 `syncManager.close()`，确保 BroadcastChannel 在挂起/卸载时释放。
2. 对所有 `runtime.onMessage`、`tabs.onUpdated` 等监听的注册点核查清理路径，纳入统一 `ListenerManager` 管理。
3. 新增内存观察工具脚本（可选）：在开发模式记录活跃高亮节点与监听器数量变化。

## 阶段五：目录与职责重组
1. 内容脚本：将选择控制（消息路由、权限校验）与高亮渲染（仅调用统一渲染器）分离，移除重复逻辑。
2. 后台：新增 `data-access` 层（DAO）封装所有 IndexedDB 读写；`SearchService` 仅做查询策略编排；`storage` 负责缓存与变更通知。
3. 公共模块：将高亮片段收集/包裹 API 合并到 `painters`，供 `selection/highlight-engine` 复用。
