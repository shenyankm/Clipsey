# 批量写入与单库 URL 索引验收

2026-10-11；基线 `3604387`，候选分支 `sheny/performance-write-index`。按用户确认，以 10,000 条为主要规模，兼顾 100 条。此阶段为本地候选，整个性能优化目标仍在进行。

单库索引解决了[上一候选](./performance-indexed-url-cache.md)的批量写入退化：10,000 条整库替换从约 2.31–2.36 秒降至 1.51–1.57 秒。收益伴随全量读取分配增加和一次性升级开销，不能据此声称所有场景更快或整体已最优。逐次样本、校准与功能验收见[原始数据](./performance-write-index-results.json)。

## 实现和数据边界

数据库 v5 在 `clips` 中增加一个 `urlKey` 索引，原有八个索引保留。派生键存于私有字段 `__clipseyUrlKey`，包含规范化基础网址、原始创建时间、ID；取消正常写入中的独立 `clipUrls` 存储和额外请求。原生索引随正文一起提交、删除、清空或回滚。

公开的基础读取、批量读取、游标、分页、关键词检索及删除响应统一去掉私有字段；不修改调用者对象。存储统计、缓存和备份继续返回既有格式。普通写入先建立快照，再计算派生键，避免 getter 使索引与实际写入值不同；保留原有验证和错误传播。

v3 升级在版本事务中回填私有键，保留原字段、附加字段和未知存储。v4 还会检查旧派生存储的结构及记录，确认后才退役；未知结构、额外字段或命名冲突会中止升级，原库保留。失败回滚后可重试。覆盖了嵌套日期、稀疏数组、数字 ID、out-of-line 主键和空值保留；这不保证所有异常旧记录都能在界面中显示。内联记录若已占用私有字段，升级安全中止，不覆盖原值；成功升至 v5 后旧版不能直接打开该库，未提供自动降级。

异常 ID/日期仍使用回退标记，旧 out-of-line 主键仍沿用全库读取。页缓存保留一个基础 URL、最多 2,500 条；密集小库和更大子集继续回退全库。查询参数优先级、创建时间/ID 顺序、高亮去重、页缓存与全量缓存共存、失效和并发规则保留。命中正文现在通过索引批量读取，并在同一只读事务中校验数量和每个不同来源网址，避免对同一来源反复解析。

## 实测结果

macOS、Node.js 22.23.2、Headless Chrome 155.0.0.0、真实 IndexedDB、独立临时目录。正文约 640 字符，带 HTML；页面读取与全量缓存夹具包含完整日期，写入夹具保留原先缺失 `updatedAt` 的输入。真实存储服务负责标准化、事务和缓存失效，仅扩展消息传输使用桩。功能结果在计时外断言。

每项先预热，再七次取中位数。写入顺序为基线、候选、候选、基线；读取第二轮交换数据规模和命中数顺序。串行测量，没有同时运行测试、构建或其它性能脚本。冷指清空应用缓存，数据库已准备好，不是磁盘冷启动或休眠后台唤醒。

| 写入，ms | 基线：第一轮 / 第二轮 | 候选：第一轮 / 第二轮 |
| --- | --- | --- |
| 10,000 条整库替换 | 2,363.8 / 2,309.0 | 1,512.8 / 1,569.6 |
| 10,000 条清空 | 519.0 / 619.1 | 511.4 / 502.1 |
| 100 条整库替换 | 12.8 / 11.9 | 9.4 / 11.5 |
| 100 条清空 | 2.9 / 2.5 | 2.8 / 3.2 |

整库替换耗时降低约 32%–36%；清空第一轮相近，第二轮减少约 117ms，不把两轮的差异概括为固定加速比例。单条添加、同高亮替换和删除的全部样本也保留在原始数据中；绝对耗时很小，不用微小差异宣传界面收益。

读取表由原始数据生成，见下表。

| 10,000 条冷读取，ms | 基线：第一轮 / 第二轮 | 候选：第一轮 / 第二轮 |
| --- | --- | --- |
| 命中 0 条 | 0.2 / 0.4 | 0.2 / 2.3 |
| 命中 1 条 | 0.2 / 0.3 | 0.2 / 1.3 |
| 命中 10 条 | 0.6 / 0.5 | 0.4 / 1.6 |
| 命中 100 条 | 2.9 / 2.7 | 2.0 / 2.8 |
| 命中 1,000 条 | 24.7 / 26.4 | 13.7 / 18.0 |
| 命中 2,500 条 | 49.3 / 42.9 | 30.6 / 41.5 |
| 命中 5,000 条 | 83.5 / 77.8 | 74.5 / 83.6 |
| 命中 10,000 条 | 82.4 / 74.3 | 81.8 / 78.2 |

1,000 条命中两轮都更快；2,500 条第一轮更快、第二轮相近。稀疏读取保持避免加载全库的收益，但亚毫秒样本的第二轮也出现了 1–2ms 的抖动。密集回退没有稳定改善。

100 条读取同样保留所有样本：规模由小到大时，全部命中约 1.4ms → 1.0ms；反序、清空大数据后约 10.8ms → 14.7ms。少量命中的反序样本也有回退，不能声称小数据所有场景改善。独立全量缓存专项中，100 条完整日期冷全量读取约 0.5 / 0.6ms → 0.6 / 0.5ms。

10,000 条完整日期冷全量读取为 63.2 / 59.6ms → 64.3 / 64.1ms，两轮分别增加约 1.1 和 4.5ms。缺少 `updatedAt` 的旧记录为 66.7 / 61.2ms → 70.0 / 70.5ms。该代价与写入收益一起保留，未声称全量读取更快。

另各做一轮 V8 分配采样，每项七次取中位数，间隔 16,384 bytes，包含被 GC 回收的对象；准备和采样分开，采样器未用于耗时表。10,000 条完整日期的冷全量读取约 20.4MB → 23.9MB，增加约 3.5MB。此全量路径在随后调整逐来源校验时没有变化。这是操作期间近似分配量，不是峰值存活堆、RSS、底层缓冲或磁盘占用；精确峰值和长期内存行为仍需后续验证。

最终原生升级验收：10,000 条 v3→v5 约 1,801.6ms，v4→v5 约 1,818.6ms。公开字段逐字段一致，未知存储和值保留，v4 的已确认派生存储被移除。基线两次 v3→v4 约 1,097.7 / 709.5ms；v5 改写正文有额外的一次性成本。每次升级仅测一次，不作为普遍上限。

采用前比较过分组写入与单库索引。分组写入未带来稳定收益；单库原型在完整日期的 10,000 条夹具中，整库替换约 2.23 / 2.22 秒 → 1.65 / 1.74 秒。反序清空大数据后，100 条原型样本存在明显回退，因而最终验收使用实际生产路径另行对照。原型、逐来源校验前的校准和最终生产样本分别保存，没有混用为最终结果。

## 功能验收和复跑

213 个单测、27 个文件通过，执行 V8 coverage；类型检查与 Chrome MV3、Edge MV3、Firefox MV2 构建通过。测试覆盖升级回滚/重试、私有字段冲突、未知派生数据保留、所有写入入口和公开读取边界、读后再写、事务失败、URL 失效，以及来源不一致时回退。coverage 不等于所有功能已验收。

最终 Chrome for Testing 构建在独立临时目录中通过 21 项验收：四项实际 10,000 条导入、页面高亮、同基础网址导航复用、删除后刷新及完整备份；其余 17 项覆盖搜索、分页、排序、popup/options 同步和备份恢复。页面高亮只批量读取两个相关正文，未加载全库；删除后重读剩余一个；完整备份返回 9,999 条且不包含私有字段。统计区分 URL 索引批量读取与全量批量读取。高亮测试副本临时授予回环地址权限。界面夹具与性能夹具不同，功能通过不是界面耗时测量。

Edge/Firefox 运行时、远端 CI、低端硬件、真实用户分布、后台休眠启动、精确峰值和磁盘空间未测。现有大 chunk 和 Firefox 发布配置警告仍存在；构建通过不代表商店发布检查通过。当前成果为局部性能改善，全量读取的分配及升级成本仍是后续取舍。
