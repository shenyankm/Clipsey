# 搜索性能优化

日期：2026-10-11；基线：`ad7e267`。延续 [上一轮优化](./performance-optimization.md)，目标仍在进行。

## 改动与行为

关键词搜索改用主键分批读取，每次最多 256 条；匹配后只保留截至当前页的主键和排序字段。用有界最大堆筛选，再读取本页记录。时间、URL、内容顺序与 IndexedDB 原索引一致，包括重复索引值的主键顺序和缺失索引值的排除。

标题排序也复用分批路径，包括无关键词查询；保留空标题、区域化标题/ID 比较，以及区域化比较相等时的原始主键顺序。全部批次和本页读取在同一只读事务中，不添加查询缓存或数据库版本。

原范围查询、unique 游标和非整数分页保留原游标路径。普通无关键词索引分页保留 count + 游标，避免为了常用第一页扫描全库。

## Chrome 实测

macOS、Headless Chrome 155.0.0.0、真实 IndexedDB、独立临时用户目录。100 条和 10,000 条合成数据，正文约 640 字符，附 HTML，包含缺失标题、重复时间/内容索引值和中文关键词。每项预热后测七次，记录中位数；两轮交换基线/优化顺序，没有与测试或构建同时运行。下表为 10,000 条场景，单位 ms，数据准备不计时。

| 场景 | 第一轮：基线 → 优化 | 第二轮：基线 → 优化 |
| --- | --- | --- |
| 内容搜索，时间降序第 100 页 | 84.7 → 55.7 | 94.5 → 63.7 |
| 网站搜索，URL 升序第一页 | 102.5 → 44.7 | 86.6 → 53.1 |
| 中文全文，内容升序第二页 | 145.5 → 52.3 | 137.2 → 52.0 |
| 无匹配项，时间升序 | 81.0 → 48.9 | 81.9 → 51.8 |
| 关键词过滤，标题升序第二页 | 50.5 → 47.5 | 55.4 → 56.4 |
| 无关键词，标题降序第 100 页 | 50.6 → 49.4 | 80.0 → 51.1 |

非标题关键词搜索在这两轮降低约 33–64%。标题排序未证明稳定的时间收益；其改进是取消一次读取所有富文本记录。100 条数据时，标题查询中位数的额外耗时不足 1ms，其余场景通常持平或更快，不据此宣称小规模总收益。

原生请求的结果数量实测：优化后的全部六种场景单次读取最多 **256 条**，标题原实现为 **10,000 条**。这是请求粒度和可达数据结构的限制，不是峰值堆字节数测量。精确总数仍扫描候选记录；排序元数据最多保留 `offset + pageSize` 项，极深页仍会增加元数据内存。

## 取舍与剩余工作

先读取全部索引主键的候选方案更慢，已撤掉；256/1024/4096 的批量比较没有证明大批次稳定更快，保留较小的 256。逐次插入有序数组的候选会随深页增加搬移成本，最终使用最大堆。

尚未测量峰值堆内存、低端硬件与真实用户数据分布，也未验证 Edge/Firefox 的运行时或远端 CI。范围/unique 的性能未优化。长页高亮已在[后续优化](./performance-highlights.md)中测量并改进；popup 启动仍需测量；现有大 chunk 与 Firefox 发布配置警告保留。
