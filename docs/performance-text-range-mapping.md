# 文本匹配边界映射与跨浏览器高亮验收

2026-10-12；基线 `1f9b913`。延续[Firefox 备份优化](./performance-firefox-backup.md)，检查长页面回退定位。数据库验收保留 10,000 条摘录，另用 100/10,000 段页面检查 DOM 扫描成本；每批绘制 20 条，不代表同时绘制全库 10,000 条。

## 最终改动

`findTextRangeInNode` 找到规范化文本后，原实现从原文开头分别扫描到起点、终点。现在一次扫描计算两个原文边界，仍逐字符处理空白折叠及大小写转换增加字符的情况。只改变私有映射函数及一个调用点，公开 API、搜索顺序、重叠前缀、已高亮匹配跳过、可见性判断、节点/Range 构造及回退优先级保留。

没有增加页面索引、跨查询缓存、设置或依赖。高亮引擎及默认逐项 8ms 让出主线程保留。新增回归检查覆盖跨元素的空白、`İ` 大小写展开、emoji 边界，以及跳过已有高亮后选择后续重叠匹配。

## Chrome 原生 DOM 对照

Headless Chrome 155.0.0.0、macOS、真实 DOM，独立临时用户目录。使用 Vite 加载源代码；只替代设置传输，定位、绘制及让出主线程使用实际实现。两种页面结构：每段包含前缀、`strong` 摘录、尾部文本；分散节点结构另含 `em` 和最后一段文本。

每项预热一次、七次取中位数。顺序为基线、样式缓存原型两轮、反向基线、最终映射候选两轮；第二轮反转段落规模、结构与 20 条高亮顺序。正常计时不强制 GC、不采样内存。每次验证 Range 文字及起始节点、绘制数量、逐项文字和完整原文；这些断言在计时内，两种实现相同，不当作下载或完整用户交互耗时。

下表为 10,000 段场景，单位 ms：

| 场景 | 第一轮：基线 → 最终 | 第二轮：基线 → 最终 |
| --- | --- | --- |
| 简单结构，页尾单次文本查找 | 25.8 → 22.1 | 25.7 → 21.7 |
| 简单结构，20 条无偏移回退恢复 | 690.4 → 638.2 | 697.1 → 657.2 |
| 简单结构，20 条带偏移恢复 | 263.0 → 268.8 | 254.9 → 258.7 |
| 分散节点，页尾单次文本查找 | 41.7 → 35.2 | 41.7 → 35.6 |
| 分散节点，20 条无偏移回退恢复 | 988.4 → 913.3 | 973.7 → 910.2 |
| 分散节点，20 条带偏移恢复 | 295.4 → 284.6 | 286.0 → 286.9 |

20 条无偏移回退恢复两轮减少约 40–75ms，约 6–8%；主要收益出现在位于页面后部的匹配。近开头和无匹配查询没有稳定改善：无匹配不调用边界映射，仍需扫描可搜索文本。带有效偏移的正常恢复也没有稳定变化，不声称默认所有高亮都更快。

100 段的单次查询约 0.1–0.8ms，接近计时粒度；第一轮小页面回退批次略慢、第二轮较快，完整样本保留，不据此宣称稳定的小数据体验提升。

## 未采用的样式缓存

另试过在一次同步搜索内用 WeakMap 复用父元素样式。它把简单/分散结构的样式读取由 30,000/50,000 次减少到 20,000/30,000 次。回退批次从 690.4 → 651.0ms、697.1 → 673.8ms，以及 988.4 → 964.2ms、973.7 → 958.7ms；页尾单次匹配收益很小，分散结构约 41.7 → 41.7/41.6ms。

该原型确实减少了样式调用，但耗时收益较小，且没有采样新增映射的分配成本。选择不引入这个缓存，只采用更少状态且页尾收益更明确的边界映射改动。原型源码快照哈希与逐次结果单独保存，不能把它的样式读取减少归到最终生产实现。

## 实际扩展验收

Chrome for Testing 153.0.8010.12 和测试用 Firefox 153.0 Nightly（build ID `20260722112722`，geckodriver 0.37.1），分别独立配置、当前构建和合成页面。Firefox 包含 Playwright 下载的补丁，采用原生 WebDriver，不代表正式发行版。

两种浏览器各 12 项实际流程通过：

- 在 10,000 段页面保存真实选区，核对绘制前的偏移和前后各 64 字符上下文。
- 导入真实 10,000 条摘录库，其中 20 条匹配测试页面；核对全库数量，按网址分页取出这 20 条，并使用返回记录恢复。其余来源不同。
- 倒序偏移恢复、重复激活不重复、清除后原文不变；移除偏移后全文回退恢复同一批 20 条，文字和完整原文一致。
- 同节点相邻摘录、外部 DOM 插入后按原偏移优先回退、CSSOM 隐藏目标时重新检查。
- CSSOM/媒体条件隐藏前置文本、目标仍可见时，仍绘制原来的重复摘录，不误选另一个。Firefox 媒体场景使用 50 个中间项、Chrome 使用 20 个，为自动化调整视口留出时间；先断言前置文本可见，再在目标绘制时断言它已经隐藏。
- Chrome 扩展/测试页无页面异常；Firefox 扩展 URL 来源的非警告脚本错误为空，不等同于监控所有浏览器服务错误。

227 个测试、28 个文件通过，执行 coverage；类型检查和 Chrome/Edge/Firefox 构建通过。脚本语法、Firefox 驱动/浏览器不存在时以失败状态退出并清理服务/配置的检查通过，正式运行后没有残留测试配置。没有重新测量存储或备份性能，这些生产源码未变。

## 复跑与边界

```sh
BASELINE_REF=1f9b913 node scripts/performance.mjs --highlights --baseline
node scripts/performance.mjs --highlights
node scripts/performance.mjs --highlights --reverse
BASELINE_REF=1f9b913 node scripts/performance.mjs --highlights --baseline --reverse
```

`--highlights` 现在同时测量独立文本搜索、有效偏移恢复及无偏移回退批次。基线加载列表包含文本搜索源码，避免混用新映射函数。性能脚本的 `CHROME_PATH` 可指定其它 Chrome；按上面模式执行时请串行运行。

实际扩展验收需先构建对应浏览器：

```sh
PLAYWRIGHT_MODULE='/path/to/playwright/index.mjs' CHROME_PATH='/path/to/Chrome for Testing' node scripts/highlight-acceptance.mjs
FIREFOX_PATH='/path/to/firefox' GECKODRIVER_PATH='/path/to/geckodriver' node scripts/firefox-highlight-acceptance.mjs
```

Firefox 脚本使用临时本地 HTTP 服务、独立浏览器配置和 Node 原生 WebDriver 请求，不增加 Selenium 依赖。`EXTENSION_PATH` 可指向相应构建。原始样本、原型、环境、源码/构建哈希及产物路径见 [performance-text-range-mapping-results.json](./performance-text-range-mapping-results.json)。

尚未采样本阶段分配或精确峰值，未测量 Firefox 时间收益、正式发行版 Firefox、Edge 运行时、真实网站分布、低端硬件和远端 CI。仍有全页文本收集和逐项回退扫描；本阶段不是“所有长页面已最优”的结论，整个目标仍在进行。
