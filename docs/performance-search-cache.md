# 受限搜索快照与事务版本验收

2026-10-12；基线 `6ef1a1d`。以 10,000 条为主、100 条为辅。延续[小记录扫描实验](./performance-search-projection.md)，采用内存快照，未新增持久化投影表、索引、数据库版本、权限或依赖。

## 结果与取舍

两轮 10,000 条热搜索约从 44–55ms 降到 0.6–6.0ms，降低约 88%–99%。查询仍扫描搜索字段以得到精确总数，并使用原有有界堆与排序；只是避免重复从 IndexedDB 读取和克隆整条富文本。每页完整记录仍从同一只读事务取回，HTML、额外旧字段与原始字段值继续保留。

代价明确：夹具 GC 后的总体存活堆约从 14.3MB 增到 25.9MB，差约 11.5MB。冷扫描需要收集字段，分配量略增；正序空查询标题排序从 49.3ms 增到 63.8ms。保留这一不利结果，不声称所有首次查询也更快。复用的收益适用于同一数据库版本上的后续查询。

## 一致性与边界

不能直接复用 `CacheManager`：它会标准化字段、补日期、过滤部分旧记录，而搜索原先直接读取数据库。新快照只保留原始 ID、标题、正文、网址和时间，不更改搜索语义。

统一的 `IndexedDB.executeTransaction` 为摘录写入纳入已有 `metadata` 表，写入符合 `MetadataRecord` 的随机版本标记，与正文一起提交或回滚。标记复用现有 `createId` 的兼容回退。所有应用的添加、更新、批量操作、替换、删除和清空均经过这一入口；升级阶段原生写入发生在建立新连接前。没有通过广播消息猜测版本。

搜索的只读事务同时覆盖正文和元数据：校验版本、扫描或复用搜索字段、取回本页记录使用同一事务快照。只在事务成功完成后发布缓存；版本不匹配时立即释放旧快照。按 `IDBDatabase` 身份存入 WeakMap，重开连接不会误用旧缓存。查询返回对象来自原生读取，没有公开缓存引用。

每个连接最多保留 10,000 条，字段权重最多 16 MiB（每行 128，加字符串 UTF-16 长度乘 2）；这是保守的资格判断，不是精确 V8 堆或 RSS 上限。超限、非字符串旧字段、不支持的匹配字段走原扫描路径。范围、unique、非整数分页及普通无关键词索引分页保留原路径。旧库或清空元数据后缺少标记时不复用，下一次正常摘录写入后才可建立快照。

浏览器开发者工具或外部代码直接写 IndexedDB 不维护该标记，可能使搜索缓存失效不及时；这类调试修改后应重开管理页。应用内写入不依赖这类原生旁路。

新增标记不能妨碍配额不足时删除正文。回归测试先证实候选会因标记请求错误而阻止删除；现在只对标记的 `QuotaExceededError` 阻止默认回滚，并在同一事务删除标记。后续搜索回退原扫描，避免复用旧结果。其他标记错误、正文写入错误及最终页面读取错误仍失败或回滚，不能返回部分结果。

## 独立耗时

macOS、Node.js 22.23.2、Headless Chrome 155、临时用户目录、真实 IndexedDB。数据与搜索夹具一致：约 640 字符正文、约 840 字符 HTML，含中文、缺失标题、重复排序键。每项预热一次、七次取中位数，完整字段、顺序与总数逐次核对。

基线两轮来自同一固定 Git 版本；候选用冻结后的最终源码正序和反序运行，全部串行，第二轮反转规模与查询顺序。没有同时测试、构建、采样或原生验收。曾误启动的两项重叠测量已排除并串行重跑。冷样本在计时前真实 upsert 同一摘录使应用快照失效，包含第一次重新扫描，不是磁盘冷启动。热样本期间不写入。计时包含结果断言，数据准备不计时，没有强制 GC。

10,000 条，单位 ms；热查询“基线 → 候选”：

| 查询及排序 | 正序 | 反序 |
| --- | --- | --- |
| 正文 `NEEDLE`，时间倒序，深页 | 52.0 → 5.7 | 52.0 → 5.6 |
| 网址 `/article/1`，网址正序 | 43.9 → 0.7 | 47.3 → 0.6 |
| 全字段 `测试`，正文正序，第 2 页 | 47.3 → 5.0 | 48.0 → 4.4 |
| 正文 `absent`，无结果 | 52.4 → 5.0 | 55.0 → 5.9 |
| 全字段 `needle`，标题正序，第 2 页 | 48.2 → 6.0 | 48.3 → 5.2 |
| 空查询，标题倒序，深页 | 50.6 → 6.0 | 48.7 → 5.3 |

每组八次热查询：基线主表 `getAll` 共 320 次、候选 0 次；冷查询双方仍为 320 次，单次最多 256 条。没有把“省去扫描请求”称为取消所有原生读取，版本与本页记录仍需读取。

冷查询同顺序，单位 ms：

| 场景 | 正序 | 反序 |
| --- | --- | --- |
| 正文深页 | 55.3 → 51.6 | 49.1 → 45.0 |
| 网址 | 58.6 → 39.3 | 43.3 → 41.4 |
| 中文全文 | 47.3 → 42.7 | 48.1 → 43.6 |
| 无结果 | 48.5 → 45.5 | 51.0 → 45.0 |
| 标题关键词 | 49.4 → 52.2 | 68.3 → 43.5 |
| 标题空查询 | 49.3 → 63.8 | 56.1 → 52.9 |

冷耗时有波动，不以这些结果宣称冷路径稳定提速。100 条正序候选冷 0.4–0.7ms、热 0.1–0.5ms；反序两项标题冷查询为 10.2/8.7ms，基线为 11.9/0.6ms，其余候选冷 0.5–0.7ms、热 0.1–0.4ms。保留阶段之间资源影响及不利样本，未单独归因。

## 写入与内存

另用原写入夹具独立运行。每项预热一次、七次中位数，两轮串行；全量替换和清空均核对数量，单条操作核对其他摘录与高亮去重。10,000 条，单位 ms：

| 操作 | 第一轮：基线 → 候选 | 第二轮：基线 → 候选 |
| --- | --- | --- |
| 添加 | 0.3 → 0.2 | 0.3 → 0.3 |
| 同高亮替换 | 0.5 → 0.3 | 0.3 → 0.2 |
| 删除 | 0.2 → 0.2 | 0.2 → 0.2 |
| 全量替换 | 1,928.8 → 1,739.9 | 1,725.4 → 1,755.6 |
| 清空 | 573.4 → 520.3 | 510.1 → 534.9 |

没有据此声称写入更快或无开销；额外元数据写入客观存在，单条亚毫秒差异不足以稳定归因。100 条及逐次样本全部保存。

独立 V8 分配采样，16,384 字节间隔，包含采样期被 GC 回收的对象，每项七次。准备、GC、结果核对与采样位置校验分开，采样器未用于上述时间表。10,000 条，十进制 MB：

| 查询 | 冷分配：基线 → 候选 | 热分配：基线 → 候选 |
| --- | --- | --- |
| 正文深页 | 32.51 → 35.66 | 32.54 → 10.92 |
| 网址第一页 | 23.81 → 25.29 | 23.77 → 1.35 |

GC 后整体存活堆约 14.33 → 25.87MB，包括夹具、模块、准备数据及快照，不能将差值当作精确缓存对象大小。不是峰值、RSS、磁盘增量、原生缓冲或长期泄漏测量，也不能把这两种查询的分配差推广到全部搜索。

## 验证与复跑

最终 274 个测试、29 个文件通过 coverage；语句 60.20%、分支 56.58%、函数 61.68%、行 60.57%。应用与两个搜索夹具类型检查、脚本语法、报告哈希及 diff 检查通过。新增覆盖排队写入、事务回滚、无标记、字段/规模/权重回退、额外旧字段、连接更换、读取失败，以及标记配额错误与其他错误的区别。

Chrome/Edge/Firefox 顺序构建通过。Chrome for Testing 153.0.8010.12 与带 Playwright 补丁的 Firefox 153.0 Nightly 各通过 14 项真实扩展管理页检查：100/10,000 条导入，冷/热搜索完整分页与总数，标题缺失及稳定顺序，富文本详情，备份字段隔离，后台保存/删除/清空可见，以及配额分支下界面确认删除和无标记新搜索。首次原生错误注入误放在管理页，已修正为实际后台写入进程，并重新完成验收。

配额检查使用真实请求错误事件，仅替换错误身份；未实际耗尽磁盘或浏览器配额。上述功能验收不是端到端界面耗时测量。既有共享 chunk >500kB 与 Firefox 发布配置警告保留。

旧持久化投影夹具已禁用临时测试库的搜索标记，避免热快照掩盖实际扫描；重跑确认每组 100/10,000 条查询分别产生 8/320 次真实扫描，一致性检查通过。这些新结果不替代上一轮历史时间表。
