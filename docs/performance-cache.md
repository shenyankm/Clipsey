# 全量缓存分配优化

日期：2026-10-11；基线：`40b5998`。延续[popup 与后台内存验收](./performance-popup.md)，以 10,000 条摘录为主要规模，同时测 100 条。

## 改动与边界

数据库读取原始记录，统一在 `CacheManager.update` 标准化一次。标准化已经创建新的数组与记录对象，缓存直接持有这些对象，移除随后重复的内部复制。冷读取入缓存前由两次标准化加一次复制，变为一次标准化。

对调用方返回数据时仍复制；输入对象/数组修改不能改变缓存，返回对象修改也不能改变其它结果。去重、无内容记录过滤、默认高亮样式、URL 索引、共享加载、失效重试和错误传播保留。没有新增依赖、权限、数据库版本或长期缓存。

## 原生 Chrome 对照

macOS、Node.js 22.23.2、Headless Chrome 155.0.0.0、真实 IndexedDB、独立临时用户目录。合成正文约 640 字符并带 HTML，每 1,000 条循环一次 URL。真实存储/事务/同步代码保留，仅扩展消息传输为空实现；不是实际 IPC 端到端耗时。

每项预热后七次取中位数；冷读在计时前清空内存缓存，保留数据库数据。第一轮先基线，第二轮先优化，串行运行且不同时测试或构建。温 URL 查询每个样本循环 1,000 次后折算单次时间。每次读取断言数量、顺序或 URL；更新单项另外由输入隔离测试验证。

| 10,000 条场景，ms | 第一轮：基线 → 优化 | 第二轮：基线 → 优化 |
| --- | --- | --- |
| 冷全量读取并返回副本 | 81.9 → 80.7 | 78.2 → 80.6 |
| 冷 URL 读取，加载并索引全库后返回命中项 | 98.4 → 80.2 | 87.0 → 77.2 |
| 仅更新内存缓存并建立索引 | 11.1 → 12.2 | 11.0 → 11.5 |
| 热全量读取并返回副本 | 0.4 → 0.3 | 0.4 → 0.3 |

两轮冷 URL 中位数降低约 11–18%；冷全量读取和单独更新未证明稳定时间收益。热 URL 两版约 0.001ms，仅表示本基准中的循环折算结果。

100 条冷 URL 基线为 0.6ms，优化为 0.8/1.0ms，增加约 0.2–0.4ms；冷全量读取为 0.7–1.2ms，更新约 0.1ms，热读基本持平。没有据此宣称小数据延迟收益。

计时之外的独立冷 URL 运行记录 `Date.now` 调用：基线每项 2N 次，优化 N 次（10,000 条：20,000 → 10,000），与移除一次标准化一致。计数器不参与时间对照。

## 分配量采样

另外使用原生 `HeapProfiler.startSampling/stopSampling`，平均采样间隔 16,384 bytes，包含被大小 GC 回收的对象；每项在计数前完成数据准备并强制 GC。对整个调用树的 `selfSize` 求和，每项七次取中位数，两轮交换运行顺序。API 字段定义见 [Chrome DevTools Protocol](https://github.com/ChromeDevTools/devtools-protocol/blob/master/pdl/js_protocol.pdl#L687)。

采样近似估计操作期间的分配量，包含临时对象；不是峰值存活堆、进程 RSS、数据库磁盘大小或精确字节计数。分配采样单独运行，不用采样器开启期间的耗时宣称时间收益。

| 10,000 条场景，十进制 MB | 第一轮：基线 → 优化 | 第二轮：基线 → 优化 |
| --- | --- | --- |
| 冷全量读取 | 24.61 → 22.42 | 24.94 → 22.40 |
| 冷 URL 读取 | 23.34 → 21.64 | 23.80 → 21.34 |
| 更新缓存并建立索引 | 4.45 → 3.67 | 4.32 → 3.64 |

冷读采样分配量降低约 7–10%，更新降低约 16–18%。100 条样本的分配量接近采样粒度且波动明显，未证明稳定改善。

原始环境、逐次时间和分配样本：[performance-cache-results.json](./performance-cache-results.json)。

```sh
BASELINE_REF=40b5998 node scripts/performance.mjs --cache --baseline
node scripts/performance.mjs --cache

node scripts/performance.mjs --cache --allocations
```

`--allocations` 可用于 `--cache` 和 `--index`，默认 Chrome 路径可由 `CHROME_PATH` 替代。缓存基线从 Git 读取 storage、cache-manager 和 clip-index 实现，不改工作树。本页原始样本对应 `d41771c` 阶段；当前工作树包含后续索引优化，复跑优化端将得到最新叠加效果。

连续峰值、低端硬件、真实 URL 分布、Edge/Firefox 运行时和远端 CI 尚未验证；后续[URL 索引优化](./performance-url-index.md)在单次构建中复用相同来源的解析结果。整个优化目标仍在进行。
