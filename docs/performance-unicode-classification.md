# Unicode 分类缓存实验：未采用

2026-10-12；基线 `8660d33`。延续[空白规范化优化](./performance-whitespace.md)。以 10,000 条摘录库为主要验收规模，同时检查小数据体验；本轮单独测量 100/10,000 段网页与每批 20 条无偏移高亮，未把段落数当作摘录库记录数。

## 决定

不合入 Unicode 分类缓存。中文与混合 Unicode 的尾部定位更快、热查询临时 JS 分配更少，但整批恢复未显示稳定收益，普通文本、稀疏空白与大量不同汉字的对照也出现较大耗时增加。结果不能证明缓存是整批变慢的唯一原因；它们同样不足以支持上线。保留 `8660d33` 的生产实现，本轮只增加穷举回归测试、不同汉字夹具、首次恢复观测与实验报告。

现有公开接口、数据库、权限与调度不变。没有引入依赖或长期字符缓存。上一轮已交付的空白规范化优化继续保留。

## 候选与正确性

原文边界映射对每个非 Latin-1 UTF-16 单元创建字符字符串，检查空白并计算单字符小写长度。四个候选只缓存该分类和长度，全文空白规范化、全文 `toLowerCase`、DOM 遍历与可见性仍逐次执行。原生小写可能展开且全文转换依赖上下文；所以没有硬编码某个 Unicode 特例，也没有用缓存代替全文转换。[ECMAScript 原生大小写转换定义](https://tc39.es/ecma262/multipage/text-processing.html#sec-string.prototype.tolowercase)。

新增测试把 U0100–UFFFF 每个代码单元按顺序重复两遍，在尾部定位 `TARGET!`，核对完整原文、Text 节点与 0–7 边界，覆盖首次分类与重复命中。它在原实现和候选都通过。已有 Latin-1、空白组合、大小写展开、跨节点、隐藏目标和重叠匹配测试继续保留。

| 候选 | 代价与测量 | 处理 |
| --- | --- | --- |
| 每次查询的 Map | 不同汉字场景采样 JS 分配约 9.34 → 10.21MB | 未采用 |
| 每次查询的分块 Uint8Array | 中文/Unicode 分配减少；每次查询另有分块原生缓冲，反序对照整批较慢 | 未采用 |
| 上下文共享分块表 | 降低重复分类，仍未建立稳定整批收益 | 未采用 |
| 上下文共享单表 | 首次非 Latin-1 查询懒分配固定 65,536 字节缓冲；以下独立对照 | 未采用 |

共享表只保留数字，不保存文本、节点或样式，直到内容脚本上下文销毁。单表最多 64KiB 原生后备存储，包装对象另外计算；分块表最多 65,280 字节后备存储及包装对象。采样 JS 分配量不包含这项原生容量，也不是净内存收益。

## 最终单表的独立耗时

Headless Chrome 155、macOS、Node.js 22.23.2、独立临时配置。只替代设置传输，使用生产文本定位、绘制与默认调度；每次核对 Range 两端、目标文字、20 个绘制结果和清除后的原文。普通夹具每段五个文本节点，稀疏夹具只在最后一段追加 Tab；不同汉字夹具每段增加两个不同代码单元，在 10,000 段中共有 20,000 种，避免只测重复字符。

正式计时执行顺序为候选正序、候选反序、基线反序、基线正序。四次均独立浏览器进程、串行运行，没有与测试、构建、分配采样或原生验收重叠。准备 DOM 后等待两个动画帧；查询预热一次，随后采样七次取中位数；首次恢复另列，整批预热后的七次恢复也取中位数。下列单位为 ms。

## 热查询分配

另起四个浏览器进程，执行基线正序、候选正序、候选反序、基线反序。计时运行全部结束后才开始分配采样，不用分配进程中的预备耗时排序。CDP HeapProfiler 间隔 16,384 字节，计入已被大小 GC 回收的采样对象。每次先准备 DOM 并 GC，仅采样一次尾部查询与边界断言；七次取中位数，每个样本核对分配位置之和等于总量。

此时共享分类表已经预热，初始化与常驻缓冲不在查询采样里。10,000 段的临时 JS 分配估计，MB 按 1,000,000 字节计算：

| 文本 | 正序：基线 → 候选 | 反序：基线 → 候选 |
| --- | --- | --- |
| Latin-1，普通空格 | 6.98 → 6.78 | 6.89 → 6.97 |
| 中文与英文混排 | 16.03 → 8.27 | 16.12 → 8.32 |
| Unicode 空白、展开与 emoji | 20.36 → 13.36 | 20.46 → 13.68 |
| 仅末尾追加 Tab | 7.86 → 7.76 | 7.81 → 7.64 |
| 20,000 个不同汉字代码单元 | 9.35 → 8.64 | 9.16 → 8.51 |

这些是临时 JS 分配估计，包含已回收对象；不是峰值堆、常驻堆、原生 DOM、ArrayBuffer 后备存储或泄漏检查。没有把热查询减少的分配当作页面总内存下降，也未声称首次大量不同字符必有收益。
