# 越界分页与计数发布时机验收

2026-10-12；基线 `50c58f2`，承接[单事务分页与精确计数复用](./performance-count-cache.md)。以 10,000 条为主、100 条为辅。

后续[深页复访的有界主键缓存验收](./performance-page-keys.md)记录有效深页的重复访问优化；本文件保留此前阶段的数据。

## 结果与实现

有无范围计数缓存提示可能越界时，先在当前只读事务中核对写入版本并取得精确总数；确认 offset 已到达或超过总数后返回空数组。提示本身不能决定返回值：插入使旧空页变为有效页时，仍取回新增正文。普通页、冷缓存和范围查询保留并行的计数/正文请求。

只对安全整数偏移、正安全整数页量及原生有效方向应用空页判断。保留 fractional、零/负页量、NaN 和无效方向原有路径与错误。没有额外缓存、公开 API、依赖、schema、权限或估算值。

实际浏览器的连续查询还揭示了发布顺序：`complete` 后置监听器可以晚于事务包装器的等待方。原先计数本身能在下一次 metadata 请求后命中，但提前检查的空页提示尚未看到它。现在在原有 oncomplete 回调通知包装器之前发布计数；finally 保留原完成处理器的 this、参数和调用。abort/失败仍不发布，只有原生事务已经完成才更新内存缓存。

## 冷查询高延迟的诊断

单独比较新建 100 条库与先写 10,000 条、clear 后重写 100 条。每个生命周期/索引七次独立重建，轮换直接原生 count、公共 count 与第 6 页；每个方法关闭/重建连接后测冷查询，随后立即测同一方法热查询。记录原生 count、版本读取及游标 row/end 的开始/结束时间，核对总数 100、页数 5、越界正文为空。准备、参考读取和打开连接不计时。

Chrome 155 收缩后的直接原生 count 和游标都可能明显变慢；初步原生计数约数毫秒，完整空页可达十几至二十几毫秒。基线的一次正文冷空页：版本读取约 0.1ms，首个游标回调约 7.7ms，计数结束约 14.4ms，游标结束约 18.3ms。该时间线表明多余游标占有明显成本；存储历史与高延迟相关，但未确定浏览器内部清理机制，不归因于某个底层实现。

最终诊断的收缩后第 6 页，单位 ms，中位数，基线 → 候选：

| 索引 | 冷正序 | 冷反序 | 热正序 | 热反序 |
| --- | --- | --- | --- | --- |
| 创建时间 | 12.1 → 3.2 | 8.1 → 12.9 | 8.3 → 0.2 | 5.9 → 0.2 |
| 正文 | 27.0 → 26.0 | 21.1 → 27.1 | 16.6 → 0.2 | 14.5 → 0.2 |

候选两轮七次热空页均没有游标事件，只读取版本。冷页仍打开游标：本轮没有消除首次计数或游标的原生高延迟，也不把偶尔更快的冷样本作为提速结论。Chrome 153 和 Firefox Nightly 的同夹具检查也通过，热空页没有游标，非法方向仍抛原生 TypeError。

诊断增加了事件计时监听器，不能当作未插桩的全程性能验收。下一表来自独立的原有分页夹具，未插桩或 CPU/分配采样。

## 未采用的候选

第一版让全部分页都等待 count，再选择是否读取正文。虽然冷/热空页变快，正常深页两轮都有回退，例如正文降序正序 59.0 → 69.5ms、反序 62.2 → 63.7ms。未保留这个排队策略。

第二版保留普通页并行，只先检查旧计数提示，但仍在后置 complete 监听器发布缓存。真实浏览器紧接冷查询的热页经常错过提示，正文越界页仍约 64–70ms。随后修正发布顺序，并重新跑正式基线与候选，未复用这两版候选的性能结论。原始探索、两版未采用候选及最终全部样本保存在 [performance-empty-page-results.json](./performance-empty-page-results.json)。

345 项测试、32 个文件通过 coverage；语句 61.16%、分支 58.27%、函数 63.13%、行 61.38%。新增加 21 个用例覆盖热越界、空库、有效方向、非法方向、特殊参数、排队插入、冷/范围原路径与旧空页在插入后变为有效页。最终回归用例在基线 11 个失败、10 个通过，候选全部通过。fake-indexeddb 不验证 WebIDL 方向枚举，该单元用例显式模拟 TypeError；三真实浏览器诊断另验证了实际枚举错误。

应用/新夹具类型检查、脚本语法及 diff 检查通过。Chrome、Edge、Firefox 顺序构建通过，既有共享大 chunk 和 Firefox 发布提示保留。

Chrome for Testing 153.0.8010.12 与带 Playwright 补丁的 Firefox Nightly 153.0，各通过 18 项原始生产构建的实际管理页检查。保留第 500 页完整正文/富文本、精确计数复用、冷/热关键词、标题、备份、后台写入/删除/清空与配额回退；新增空列表的实际普通搜索检查：版本读取完成、精确总数 0、0 次重新计数、0 次两类游标、0 次全量正文读取、0 条显示行。

首次界面夹具误在空列表中点击已隐藏的表头，Chrome 检查中途失败。已修正为在有数据时设置排序，清空后通过实际搜索输入触发查询，并重新运行 Chrome 与 Firefox；失败日志单独保留，未当作成功验收。

每种主环境四轮串行：基线正序、候选正序、候选反序、基线反序；每项七次取中位数。正式生产源码/夹具冻结后测量；编译、测试、界面检查均在时间测量结束后运行。真实 IndexedDB、独立临时配置，不访问用户摘录。主环境 macOS / Node 22.23.2，Headless Chrome 155.0.0.0（安装版 155.0.8059.39）；数据正文约 640 字符、HTML 约 840 字符，含中文、缺标题、重复索引值。真实界面使用更短正文，功能验收不是点击到绘制时间。
