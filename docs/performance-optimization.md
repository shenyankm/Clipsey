# 持续性能优化记录

日期：2026-10-11。存储/查询基线：`5b8caa1`。目标仍在进行，以下仅记录已实施并验收的优化，不声称整个项目已达到性能上限。后续优化见 [搜索性能记录](./performance-search.md)与[长页面高亮记录](./performance-highlights.md)。

## 已实施

- 新增/删除改为通过主键和已有 `highlightId` 索引访问目标；去重、删除和写入仍在同一事务中。同步消息携带数量增量，整体替换使用未指定增量的通知，不再为了通知而读取或计数全部记录。无生产调用方的模拟 `storage.onChanged` 门面已删除，设置仍使用浏览器原生 storage API。
- 不分页且不要求 unique 游标的全量读取使用原生 `getAll`；逆序读取在返回数组上反转。分页、offset 和 unique 查询保留游标路径，错误仍向上传递。
- 摘要管理连续输入合并 180ms；输入变化立即使旧请求失效。排序、翻页、刷新和显式搜索取消待执行的输入查询；卸载组件时取消定时器。新增/整体替换的通知回到第一页，避免页码变化与刷新重复查询。
- 摘要管理专用的表格、搜索框、单选、标签、分页和弹窗组件移入按需加载组件，设置入口保留基础页使用的组件；补齐搜索提示 Tooltip 的本地注册。

## 真实 Chrome 对照

macOS、Node.js 22.23.2、Headless Chrome 155.0.0.0、独立临时用户目录、真实 IndexedDB。每项预热一次，测七次并取中位数；两轮分别先基线后优化、先优化后基线。时间单位 ms，不包含数据准备。写入测量保留源码中的同步发送路径，用空实现替代扩展消息传输；不等同于端到端点击耗时。

| 1 万条数据场景 | 第一轮：基线 → 优化 | 第二轮：基线 → 优化 | 结论 |
| --- | --- | --- | --- |
| 新增单条 | 52.3 → 0.2 | 45.3 → 0.3 | 去除全库读取与计数，明显改善 |
| 替换同页面同高亮 | 42.6 → 0.3 | 43.7 → 0.3 | 每次样本均准备待替换的旧 ID，不混用纯更新路径 |
| 删除单条 | 46.6 → 0.2 | 53.4 → 0.2 | 主键读取及删除，返回被删除记录供页面清理高亮 |
| 全量读取 | 64.9 → 40.5 | 62.6 → 40.6 | 减少逐条游标回调，降低约 35–38% |
| 清空 | 367.1 → 392.2 | 504.1 → 393.9 | 波动大，未证明稳定收益；仍等待原生事务完成 |

写入还测了 100 条记录：优化后的新增/替换/删除中位数为 0.2–0.6ms。深页与热缓存 URL 查询未观察到稳定改善，不宣称本轮收益。原始逐次样本与环境见 [performance-optimization-results.json](./performance-optimization-results.json)。

组件拆分前后，设置页静态 JS 依赖由 **943,990 → 695,486 bytes**，减少约 26%；popup **696,736 → 697,298 bytes**，基本不变。此比较是同一优化轮中拆分组件前后，不包含 CSS、动态加载的摘要管理、缓存收益，也没有据此推算启动时间。首次进入摘要管理仍需加载其延后依赖。
