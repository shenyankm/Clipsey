# 缓存读取与字段处理验收

2026-10-11；基线 `59a360b`，候选分支 `sheny/performance-cache-raw-reads`。继续以 10,000 条为主、100 条为辅。整个性能优化目标仍在进行，此阶段仅本地提交。

内部缓存读取减少了一次字段处理，10,000 条完整日期记录的全量冷读取约由 60ms 降至 57–58ms，V8 分配采样减少约 9%–11%。此次没有更换 schema 或索引表示。延续[单库索引验收](./performance-write-index.md)；逐次样本、未采用的原型和功能验收见[原始数据](./performance-cache-snapshot-results.json)。

## 范围和边界

先前的全量缓存通过公开查询 API 读取，逐条删除私有索引字段后，缓存又逐条标准化并生成对外摘录。现在两个私有加载器将原生 IndexedDB 快照直接交给现有 `CacheManager` 标准化，避免中间的删除和数组映射；缓存存储、URL 索引及返回对象只含原有公开字段。

全量读取仍等待只读事务完成，使用同一 `createdAt_id` 索引倒序。异步请求失败仍抛出 `QUERY_ERROR` 并保留原始 cause，不能缓存成空数组；失败后可重试。页读取保留命中数量、不同来源网址校验、旧记录回退和 2,500 条上限。失效、并发、去重、查询优先级、顺序和返回对象隔离均沿用现有缓存逻辑。

公开的 `IndexedDB.get/getAllData`、查询、分页及删除响应继续去掉私有字段；没有提供返回原始对象的公开选项。数据库仍为 v5，所有写入、升级和备份格式沿用上一阶段。原始记录及额外旧字段保留在数据库中；缓存与备份延续原先的标准化规则。

## 未采用的方案

先在独立实验数据库中比较紧凑字段：只保存基础 URL，由复合索引使用原日期和 ID，另加一个只包含异常旧记录的索引。第一轮全量读取 71.4ms → 64.1ms，第二轮 71.3ms → 76.4ms；第二轮 10,000 条写入 1,884.8ms → 1,946.6ms，分配采样 26.12MB → 25.87MB。未见足以支持增加索引和升级逻辑的稳定收益，未采用。

随后在相同 v5 数据上比较公开读取、内部直接标准化和复制去字段。两轮内部直接标准化的冷全量读取约 65.4 / 62.1ms → 62.3 / 58.3ms，分配约 26.82 / 27.19MB → 22.45 / 22.73MB。复制去字段为 66.8 / 61.5ms，没有稳定耗时改善；也未改动公开读取。原型使用两套数据库和独立缓存，不作为最终生产收益。

## 生产对照

macOS、Node.js 22.23.2、Headless Chrome 155.0.0.0，真实 IndexedDB，独立临时目录。正文约 640 字符并带 HTML，分别测试完整日期与缺少 `updatedAt` 的输入。扩展消息传输使用桩，存储、缓存及索引使用真实源码。每项预热一次，再七次取中位数；基线、候选、候选、基线串行运行，没有同时测试、构建或跑其它性能脚本。

冷指清空应用缓存，数据库已准备好，不是磁盘冷启动或休眠后台启动。

| 冷全量读取，ms | 基线：第一轮 / 第二轮 | 候选：第一轮 / 第二轮 |
| --- | --- | --- |
| 10,000 条，日期完整 | 60.3 / 59.9 | 58.4 / 56.6 |
| 10,000 条，缺少 updatedAt | 68.8 / 65.3 | 63.1 / 66.4 |
| 100 条，日期完整 | 0.6 / 0.5 | 0.5 / 0.5 |
| 100 条，缺少 updatedAt | 1.0 / 0.6 | 0.6 / 0.7 |

完整日期的主要规模两轮分别减少约 1.9 和 3.3ms；缺少日期的第二轮增加约 1.1ms，不声称所有旧记录场景也稳定更快。小数据绝对耗时很小，不把亚毫秒差异解释为界面体验变化。

另在各轮耗时测量结束后执行 V8 分配采样，间隔 16,384 bytes，七次取中位数，包含被 GC 回收的对象。准备、结果核对不计入采样；采样器未用于上面的耗时表。

| 10,000 条冷全量读取，十进制 MB | 基线：第一轮 / 第二轮 | 候选：第一轮 / 第二轮 |
| --- | --- | --- |
| 日期完整 | 24.41 / 24.83 | 22.11 / 22.16 |
| 缺少 updatedAt | 24.57 / 24.90 | 22.66 / 22.03 |

这是操作期间近似 V8 分配量，不是峰值存活堆、RSS、底层缓冲、磁盘空间或长期无泄漏证明。完整日期约减少 2.3–2.7MB；此前原型约减少 4.4MB，不能将该值当成最终生产收益。

## 页面读取

相同生产页面读取夹具，分别覆盖 100 / 10,000 条和不同命中比例，七次取中位数；第二轮反转规模与命中数顺序。结果 ID、顺序、精确查询优先和后续全量数量在计时外断言。

| 10,000 条冷页面读取，ms | 基线：第一轮 / 第二轮 | 候选：第一轮 / 第二轮 |
| --- | --- | --- |
| 命中 0 条 | 0.1 / 0.6 | 0.1 / 2.2 |
| 命中 1 条 | 0.2 / 0.6 | 0.2 / 1.4 |
| 命中 10 条 | 0.4 / 0.7 | 0.3 / 1.6 |
| 命中 100 条 | 2.2 / 1.9 | 1.7 / 3.3 |
| 命中 1,000 条 | 15.5 / 16.5 | 11.3 / 19.3 |
| 命中 2,500 条 | 35.1 / 48.1 | 24.9 / 47.6 |
| 命中 5,000 条 | 77.5 / 80.1 | 87.0 / 78.2 |
| 命中 10,000 条 | 72.5 / 69.4 | 71.5 / 69.1 |

页面耗时有波动：1,000 条命中第一轮减少约 4.2ms，第二轮增加约 2.8ms；2,500 条第一轮减少约 10.2ms，第二轮相近。密集回退也没有稳定加速。100 条全部命中为 0.9 / 24.3ms → 1.1 / 23.3ms，反序清空大库后的背景存储工作和 GC 可能影响样本，未将其归因为确定的单一原因。

另各做一轮页面分配采样，基线正序、候选反序。10,000 条中命中 1,000 条约 2.46MB → 2.18MB，命中 2,500 条约 6.19MB → 5.63MB；全量命中回退约 24.44MB → 22.26MB。其它比例也保留全部样本，256 条命中存在回退，零样本不表示零分配。

分配准备复用只读数据库夹具：切换数据组时才重新写库，每个样本仍清空应用缓存并强制 GC。两边使用同一新准备逻辑；操作断言和页面 verify 确认数据集未被错误复用。没有把写库与采样混在一起。

## 功能验收和复跑

216 个单测、27 个文件通过，执行 V8 coverage；类型检查及 Chrome MV3、Edge MV3、Firefox MV2 构建通过。新增检查覆盖冻结的带私有字段快照、全量/页缓存的公开返回、调用者修改隔离，以及异步读取的错误码、cause 和重试。全量读取次数改用实际 `createdAt_id` 原生索引观测，避免测试依赖旧公开查询调用。原有升级、事务、备份、旧 ID、顺序与并发测试保留。

最终构建在 Chrome for Testing 153.0.8010.12 通过 21 项实际流程：10,000 条导入后仅读取两个相关正文并高亮，同基础网址导航复用，删除后刷新，备份包含 9,999 条且不含索引字段；另覆盖搜索、分页、排序、popup/options 同步、备份恢复和页面异常。临时配置和截图位置保存在原始数据中。功能验收不是界面耗时测量。

```sh
BASELINE_REF=59a360b node scripts/performance.mjs --cache --baseline --allocations
node scripts/performance.mjs --cache --allocations
BASELINE_REF=59a360b node scripts/performance.mjs --page-cache --baseline
node scripts/performance.mjs --page-cache

BASELINE_REF=59a360b node scripts/performance.mjs --page-cache --baseline --allocations
node scripts/performance.mjs --page-cache --reverse --allocations
BASELINE_REF=59a360b node scripts/performance.mjs --key-layout --baseline --allocations
```

`--key-layout` 为隔离的原型比较，包含字段隔离、输入保留、异常旧记录回退、删除标记及结果断言。指定基线可重现 v5 公开读取与原型的对照；不更改工作树或用户数据库。

本轮没有重测写入性能和升级耗时，因为这些实现和 schema 未变；也没有验收 Edge/Firefox 运行时、远端 CI、真实用户数据、后台休眠启动、精确峰值或低端硬件。既有大 chunk 与 Firefox 发布配置警告保留。当前收益是局部改善，整体目标尚未达到完成判据。
