# 已高亮重叠检查：到匹配末端停止

2026-10-12；基线 `1539a99`。以 10,000 条摘录库为主要验收规模，兼顾小数据；本轮分别测 100/10,000 段网页和每批 20 条无偏移高亮，真实库与消息链路另用原生扩展验收。延续[Unicode 分类缓存实验](./performance-unicode-classification.md)，未恢复该缓存候选。

## 改动与证据

全文匹配找到原文边界后，`isRangeHighlighted` 检查相交文本节点的祖先高亮标记。原实现对未高亮的匹配继续读完全部节点长度，即使已经超过匹配末端。当前在检查完包含末端的相交节点后返回 `false`；剩余节点的起点至少等于结束位置，不可能重叠。结束判断放在相交分支内，匹配前的节点不增加结束位置比较。

这只减少重叠检查中的无关扫描。收集可见文字、全文大小写与空白处理、原文边界映射、最终 Range 构造仍保持原逻辑；没有缓存节点、文字或样式，没有增加接口、依赖、权限、数据库变更或调度配置。

新增回归测试在匹配后放一个长 Text，用 getter 计数验证匹配仍正确且不读取其长度。旧实现测试失败，确实多读一次；最终实现通过。原有跨节点、已高亮重叠、重复匹配、空白与 UTF-16 展开测试继续通过。可证明检查会在匹配末端停止；不能据此声称全文查找不再遍历整页。

## 独立耗时对照

Headless Chrome 155、macOS、Node.js 22.23.2、临时配置；五种布局，每段五个文本节点，稀疏布局只在末尾追加 Tab，不同汉字布局在 10,000 段中有 20,000 个不同代码单元。准备页面后等待两个动画帧，查询预热一次，随后采样七次取中位数。每次核对 Range 两端与文字；恢复阶段使用生产定位、绘制、默认调度，仅替代设置传输，确认 20 个目标和清除后的原文。
