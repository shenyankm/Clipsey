# 普通深分页的主键游标验收

2026-10-12；基线 `ec68c91`。以 10,000 条摘录为主、100 条为辅。延续[搜索分页](./performance-search.md)，针对无关键词的普通分页，不改变关键词匹配、标题本地化排序或高亮调度。

后续的[精确计数复用与单事务分页](./performance-count-cache.md)已将 total 与 data 合并到同一读取快照；本报告记录该变更之前的基线和结果。

## 结果与实现

10,000 条、偏移 9,000、每页 20 条，创建时间排序的完整分页：Chrome 两轮约从 58–60ms 降至 43–49ms；测试用 Firefox Nightly 约从 61–66ms 降至 2ms。Chrome 的精确总数查询仍占明显时间，未取消计数，也不将数据读取的提升当作全程提升。

生产代码只修改 `IndexedDBQuery.getAll`。安全整数 offset 在 256 至 `2^32 - 1`、安全整数 limit 在 1 至 100、普通正反向查询时，使用 `openKeyCursor` 跳过前面的记录并选出本页主键，然后在**同一只读事务**内用主键取回本页完整正文。得到最后一个所需主键后立即开始读取，不多推进一次游标。并行请求的返回数组保持选择顺序。

没有全库主键数组、永久缓存、新依赖、权限、schema 或索引变更。最多保留本页 100 个主键；这是可达数组的记录数边界，不是峰值堆、RSS 或浏览器内部缓冲的字节上限。底层仍需跳过记录，不是键集分页或 O(1) 随机跳页。

首页、浅页、unique、非整数 offset/limit、无界读取及大于 100 条的页量沿用原路径。范围、重复键和顺序保留。返回值仍使用 `IndexedDB.readRecord` 去掉私有 URL 字段，不标准化正文或补日期；额外旧字段、数字主键和嵌套 Date 均保留。

`paginate` 的计数和取页仍是两次只读事务，这是原有行为；本轮不声称并发写入时 total 与 data 属于同一快照。新的主键选择与正文读取本身属于同一快照，排队写入在下一次读取可见。读取错误仍使整页失败，不返回部分正文。

## 测量方法

macOS、Node.js 22.23.2。Chrome 为现有 Headless Chrome 155；Firefox 为带 Playwright 补丁的 153.0 Nightly，geckodriver 0.37.1。真实 IndexedDB、独立临时配置与合成数据，不访问用户摘录。正文约 640 字符、HTML 约 840 字符，含中文、缺失标题、重复索引值和未指定 `updatedAt` 的输入。

比较主表、创建时间、网址、正文和有范围的复合时间/ID 索引，正反方向，首页、浅页、偏移 260、半程、深页、末页与越界。范围约覆盖 60% 的记录。每项预热一次、七次取中位数；每个样本逐字段、顺序和精确总数对照原生全量参考结果。断言包含在总耗时中，准备和写入不计时。

两轮分别正常顺序与反转规模/索引/方向/页码，浏览器、构建和测试全部串行。正式候选在源码冻结后重新运行；基线从固定 Git 版本加载数据库源码。夹具轮换执行三种读取策略，正式表格只取生产方法 `current`，不混入原型耗时。JSON 保存正式路径的所有样本，以及原型阶段的三种策略数据。

## 小数据、边界与取舍

100 条浅页/普通页完整耗时范围：Chrome 正序基线 0.4–1.6ms、候选 0.3–1.3ms，反序 0.3–1.4ms / 0.3–1.6ms；Firefox 正序 0–1ms / 0–1ms，反序 0–2ms / 0–1ms。Firefox 计时量化到毫秒，0 不等于没有成本；不据此声称稳定小数据提速。

偏移 260 附近绝对收益小，存在不利样本：Chrome 反序主表正向数据 1.0 → 1.4ms、完整页 10.1 → 11.5ms；复合范围正向完整页 18.5 → 19.4ms。Firefox 反序主表倒序完整页 8 → 10ms。没有仅展示深页。

首页/浅页也有波动：Chrome 反序创建时间升序首页 25.3 → 30.7ms，其中未改动的 count 阶段 24.6 → 29.5ms、数据阶段 0.7 → 0.9ms。Firefox 部分主表浅页增加约 2ms。没有单独归因，不宣称所有页或所有机器均无回退。

主键路径增加本页的主键查找请求，不是减少总请求数。Chrome 长正文索引计数仍约 60ms，数据请求变快不能消除该成本。没有删除索引、取消精确 total 或引入估算值。

## 未采用的批量主键方案

原型用 `getAllKeys(query, 10001)` 读取命中主键，逆序时反转，再取本页正文。方法语义见 [IDBIndex.getAllKeys](https://developer.mozilla.org/en-US/docs/Web/API/IDBIndex/getAllKeys)；不要求新版方向选项或 `getAllRecords`。

初始 Chrome 两轮的创建时间升序深页，完整分页分别为游标 61.2 / 65.4ms、批量主键 54.9 / 61.6ms、主键游标 51.7 / 54.9ms。批量主键保留最多 10,000 个主键，却通常不如主键游标；Firefox 主表偏移 260 的批量方案约需 15–16ms，原游标约 7–8ms。未接入批量方案，原型明确限制最多 10,000 个命中，不能作为超限的生产实现。

初始 Chrome 原型未包含偏移 260，保存其原始夹具源码快照；正式验收增加该案例并重新跑基线和候选。探索数据单列，提升比例只使用正式生产路径结果。

Chrome/Edge/Firefox 顺序构建通过；原有共享 UI 大 chunk 和 Firefox 发布配置提示保留。没有更新依赖或构建配置。

Chrome for Testing 153.0.8010.12 和同一 Firefox Nightly 加载**原始生产构建**，各通过 16 项实际扩展管理页检查。新增无关键词跳至第 500 页（偏移 9,980）的检查：总数 10,000、全部 20 个 ID/顺序正确、一个原生主键游标、20 次正文主键读取、0 次全量读取；详情显示第一个目标的原 HTML。回到第一页后继续原有冷/热关键词、标题排序、富文本、备份、后台保存/删除/清空、配额回退和异常检查。
