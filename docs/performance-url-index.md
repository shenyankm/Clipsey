# URL 索引构建优化

日期：2026-10-11；基线：`d41771c`。以 10,000 条摘录为主要规模，同时检查 100 条，延续[全量缓存优化](./performance-cache.md)。整个性能优化目标仍在进行。

## 改动与取舍

`buildClipIndex` 在单次构建中保存原始来源 URL 对应的索引键，同一来源只解析一次。连续和分散重复均可复用，无效来源的空键数组也会复用。构建结束后临时表不再保留；每次重建重新解析，避免来源变更后沿用旧结果。

原有 URL 规范化、精确查询优先、基础路径回退、桶内顺序、对象身份和高亮去重保留。没有新增依赖、权限、数据库版本或永久缓存。临时表大小随不同原始来源数增长；所有来源均不同时会增加分配和耗时，以下单独披露该成本。

仅复用相邻来源的候选不能改善分散重复；按连续分组批量添加的候选增加了全不同来源的成本。保留构建内临时表，不增加分布探测或跨构建缓存。

## 原生 Chrome 对照

macOS、Node.js 22.23.2、Headless Chrome 155.0.0.0，独立临时用户目录。两轮串行运行，顺序为基线 1、优化 1、优化 2、基线 2，不同时运行测试或构建。每种场景预热后七次取中位数。索引基准使用真实构建函数，数量断言在操作内，完整桶顺序、引用和查询结果断言在计时外。

合成来源分为：每十条连续复用同一 URL、每 N/10 条循环复用 URL、全部不同。分别测无查询参数和带乱序/重复查询参数的 URL。

| 10,000 条索引构建，ms | 第一轮：基线 → 优化 | 第二轮：基线 → 优化 |
| --- | --- | --- |
| 无查询参数，连续重复 | 7.2 → 1.2 | 6.6 → 1.1 |
| 无查询参数，分散重复 | 6.8 → 1.0 | 6.9 → 1.0 |
| 无查询参数，全部不同 | 7.5 → 8.8 | 7.4 → 8.8 |
| 带查询参数，连续重复 | 22.2 → 2.9 | 22.5 → 2.9 |
| 带查询参数，分散重复 | 25.3 → 2.8 | 25.4 → 2.8 |
| 带查询参数，全部不同 | 24.4 → 26.0 | 25.1 → 25.4 |

重复来源构建中位数降低约 83–89%；全部不同增加约 0.3–1.6ms。100 条索引构建两版均为 0–0.3ms，接近时钟粒度；0ms 不代表没有耗时，不据此宣称体验收益。

## 完整缓存读取链路

复用 `--cache` 基准：真实 IndexedDB，合成正文约 640 字符并带 HTML，10,000 条中每 1,000 条循环复用 URL。真实存储、标准化、索引、同步代码保留，仅替代扩展消息传输；这些数字不包含实际跨进程 IPC。冷读先清空内存缓存，保留数据库数据。

| 10,000 条，ms | 第一轮：基线 → 优化 | 第二轮：基线 → 优化 |
| --- | --- | --- |
| 冷全量读取并返回副本 | 70.4 → 66.3 | 67.8 → 67.2 |
| 冷 URL 读取，加载并索引全库后返回命中项 | 70.2 → 64.1 | 67.2 → 59.2 |
| 更新缓存并建立索引 | 11.7 → 4.8 | 12.5 → 4.6 |
| 热全量读取并返回副本 | 0.2 → 0.2 | 0.2 → 0.1 |

缓存更新降低约 59–63%，冷 URL 读取降低约 9–12%；索引自身 83–89% 的收益不能套用于整个读取链路。冷全量读取两轮差异约 1–6%，热读取没有稳定收益。

100 条冷全量读取为 0.6 → 0.9 / 0.6ms，冷 URL 为 0.5 → 0.6 / 0.5ms，更新约 0.1ms。未证明小数据读取延迟改善，第一轮增加约 0.1–0.3ms。热 URL 循环折算两版约 0.001–0.0024ms，未证明收益。

## 分配量采样

索引构建另外用原生 `HeapProfiler.startSampling/stopSampling` 采样：平均间隔 16,384 bytes，包含被大小 GC 回收的对象，准备数据和强制 GC 在计数前完成。调用树 `selfSize` 求和，每项七次取中位数，两轮交换运行顺序。采样与计时独立运行。

| 10,000 条索引构建，十进制 MB | 第一轮：基线 → 优化 | 第二轮：基线 → 优化 |
| --- | --- | --- |
| 无查询参数，连续重复 | 1.45 → 0.29 | 1.56 → 0.38 |
| 无查询参数，分散重复 | 1.48 → 0.36 | 1.59 → 0.26 |
| 无查询参数，全部不同 | 2.37 → 2.71 | 2.10 → 2.73 |
| 带查询参数，连续重复 | 8.75 → 1.12 | 8.77 → 1.26 |
| 带查询参数，分散重复 | 8.93 → 1.20 | 9.12 → 1.28 |
| 带查询参数，全部不同 | 10.56 → 10.98 | 10.40 → 11.08 |

重复来源采样分配量降低约 74–87%；全部不同增加约 0.3–0.7MB 临时分配。该值估计操作期间的分配，包含临时对象，不代表峰值存活堆或精确字节数；临时表可回收不等于已测得峰值没有增加。100 条样本接近采样粒度，不宣称稳定分配收益。

环境、逐次时间和采样结果：[performance-url-index-results.json](./performance-url-index-results.json)。

