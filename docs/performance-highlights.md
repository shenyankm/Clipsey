# 长页面高亮性能优化

日期：2026-10-11；基线：`287ab8c`。延续[搜索优化](./performance-search.md)。摘录数据库的主要验收规模为 10,000 条，同时兼顾小数据体验；本轮另外测量 100 与 10,000 段网页，恢复其中 20 条高亮，不代表同页绘制 10,000 条高亮。

后续[动态样式补充验收](./performance-ui-validation.md)已覆盖前置文本隐藏、目标仍可见的 CSSOM 与媒体查询组合，并提供可复跑原生扩展脚本；[文本边界映射与跨浏览器验收](./performance-text-range-mapping.md)进一步覆盖真实 10,000 条库、全文回退及 Firefox 运行。下面保留原阶段结果与当时的边界。

## 改动

保存选区时只保留前后 64 字符的上下文，取得后文即停止遍历，不再拼接整页文本。同一次同步遍历中，一个父元素只读取一次样式；下次遍历重新检查。

多个未缓存的有效偏移在一次遍历中转换成实时 Range，只保留目标边界。保留输入顺序、逐项校验、原有定位回退、取消行为和每项默认 8ms 让出主线程。绘制前检查目标文本、边界与可见性；观察到外部 DOM/属性变化则放弃准备结果。绘制自身的同步 DOM 修改不清空其他实时 Range，结束或取消时断开观察。

没有新增依赖、数据库版本、权限或永久页面节点索引。

## Chrome 实测

macOS、Node.js 22.23.2、Headless Chrome 155.0.0.0、临时用户目录。每个场景预热后测七次，取中位数；第一轮先基线，第二轮先优化，串行运行且不同时测试/构建。数据准备不计时。简单段落有三个文本节点，较碎段落有五个；测量包含逐次正确性断言。

下表为 10,000 段场景，单位 ms。完整激活包含真实 DOM 绘制、默认等待和逐项让出，仅设置传输使用空响应；该计时不是实际扩展 IPC 的端到端耗时。

| 场景 | 第一轮：基线 → 优化 | 第二轮：基线 → 优化 |
| --- | --- | --- |
| 简单段落，页面中部保存上下文 | 20.0 → 8.7 | 19.9 → 9.3 |
| 较碎段落，页面中部保存上下文 | 33.8 → 14.1 | 31.6 → 14.3 |
| 简单段落，页面尾部保存上下文 | 19.9 → 17.8 | 19.4 → 18.4 |
| 较碎段落，页面尾部保存上下文 | 32.3 → 28.4 | 32.3 → 28.4 |
| 简单段落，20 条偏移定位 | 185.2 → 16.2 | 183.4 → 15.8 |
| 较碎段落，20 条偏移定位 | 308.7 → 25.0 | 289.2 → 23.7 |
| 简单段落，完整激活 20 条 | 433.6 → 254.6 | 428.1 → 264.0 |
| 较碎段落，完整激活 20 条 | 578.6 → 291.2 | 563.3 → 292.7 |

偏移定位降低约 91–92%，完整激活降低约 38–50%。页面开头的上下文采集由 22–33ms 降至计时精度以内（样本 0–0.1ms），不解释为零成本。完整激活的样式读取由简单段落 286,534 次降至 18,122 次，较碎段落 477,530 次降至 27,172 次。

100 段时，20 条偏移定位从 1.8–3.4ms 降至约 0.2ms；完整激活的优化中位数为 183.6–200.1ms，基线为 194.9–201.7ms，未证明小页面完整激活的稳定收益，也未观察到稳定退化。上下文采集中位数为 0–0.3ms。

原始环境与逐次样本：[performance-highlights-results.json](./performance-highlights-results.json)。样式读取计数与结构上限不是峰值堆字节数测量。

## 验证

- 全套测试：24 个文件、181 个测试通过；类型检查与 Chrome/Edge/Firefox 构建通过。
- 单元测试覆盖原上下文公式、Unicode、跨节点/空白、隐藏节点、尾部截断、未访问尾部、样式读取失败重试、偏移边界/乱序/重复/非有限值、同一文本节点上的实时 Range、外部插入和取消清理。
- Chrome for Testing 153.0.8010.12 加载实际构建，通过 8 项扩展消息验收：原生选区保存的偏移/上下文、倒序恢复 20 条、重复激活、清理保留原文、同节点相邻摘录、外部插入回退、CSSOM 隐藏目标时重新校验，以及无页面异常。原始结果位于 JSON 的 `chromeAcceptance`。
- 构建的 content 脚本由约 25.30kB 增至 26.65kB；共享 UI 大 chunk 与 Firefox 发布配置警告仍存在。

## 剩余边界

尾部单条选区仍需计算前方文本长度；本轮没有引入长期页面索引。峰值堆内存、低端硬件、真实页面分布、Edge/Firefox 运行时和远端 CI 尚未验证。已检查 CSSOM 隐藏当前目标，但 CSSOM 或媒体条件仅改变前置文本可见性、目标仍可见的组合尚未验收。popup 启动与模块成本已在[后续记录](./performance-popup.md)中采样，整个优化目标仍在进行。
