## 结果与实现

Chrome 155 两轮测量中，创建时间深页复访约 19–23ms → 0.3–0.4ms，正文深页复访约 50–55ms → 0.3–0.4ms。复用同一页的主键省去索引定位和游标推进；首次访问及未访问过的下一深页仍走原生游标，不宣称这类查询已提速。Firefox 也减少复访游标，但毫秒量化使部分结果只能辨认到 0–1ms，0 不代表零成本。

复用现有按连接保存的精确计数状态，每个连接最多保存 16 页、1,600 个字符串主键，并限制字段权重为 256 KiB。字段权重按每页 128 字节、每主键 32 字节加 UTF-16 长度估算；这不是实际堆、峰值或 RSS 上限。按访问更新顺序并淘汰旧页，不缓存正文或返回对象。

只缓存 clips 无范围查询、偏移 256 至 uint32 上限的安全整数、1–100 条安全整数页量及 next/prev（含 asc/desc 别名）。键包含索引、方向、offset、页量。浅页、范围、unique 方向、特殊参数、其他表、非字符串主键和超预算页保留原路径。没有新依赖、数据库 schema、权限或公开 API。

每次复访在同一 clips/metadata 只读事务中读当前版本、核对计数，再执行原生 get 读取本页正文。版本不同或缺少标记时丢弃旧状态；同数量的排序变化也会失效。查询成功且事务完成后才发布主键，并核对该事务实际读到的版本，避免挂到另一版本的计数状态。关闭/替换连接不带走缓存。保留查询失败、事务失败、配额回退和私有索引字段清理。

## 100 条小数据

偏移 80 的末页不进入缓存。Chrome 正序运行冷首屏范围 0.4–0.9 → 0.4–0.9ms，热首屏 0.3–0.5 → 0.4–0.5ms；冷末页 0.4–1.3 → 0.5–1.3ms，热末页 0.4–0.9 → 0.4–0.9ms。

Chrome 反序先经历 10,000 条再 clear 重写 100 条，冷首屏范围 0.3–12.6 → 0.3–12.7ms，冷末页 0.5–1.4 → 0.5–1.4ms，热末页 0.5–1.0 → 0.5–0.9ms。存储历史相关的冷高延迟仍在。Firefox 两轮冷/热首屏与末页均落在 0–1ms，量化不足以证明小数据收益。热越界页继续复用前阶段空页优化。

## 原型与正式测量

新增 `tests/performance/page-keys.ts` 先验证主键原型，覆盖五个无范围来源（含 createdAt_id）及两个方向、写入后顺序和总数失效。原型使用独立缓存并多读一次版本，通过测试夹具访问私有计数器，不是应用实现。保留初始 Chrome 正序、固定基线 Chrome 反序及固定基线 Firefox 正序的原型样本；不用作上述生产收益数字。

正式结果使用原有、未修改的 `tests/performance/pagination-count.ts`，在两浏览器分别串行运行基线正序、候选正序、候选反序、基线反序，共八轮。每项七对冷/热样本，含第一页、深页、越界、插入/删除后的第一页；每个样本核对总数、原生顺序和完整字段。生产源码及夹具冻结后测量，测试、类型检查、构建和界面验收在测量结束后顺序执行，无 CPU/分配插桩。

macOS，Node 22.23.2；主测安装版 Chrome 155.0.8059.39，Headless UA 155.0.0.0；Firefox 带 Playwright 补丁的 Nightly 153.0 / geckodriver 0.37.1。独立临时配置、合成数据和随机本地来源，不访问用户摘录。正文约 640 字符、HTML 约 840 字符，含中文、缺标题与重复索引值。实际界面使用更短正文，是功能验收，未测点击到绘制耗时。
