# 日期标准化与后台内存观测

日期：2026-10-11；基线：`90d1311`。以 10,000 条为主，兼顾 100 条，延续[URL 索引优化](./performance-url-index.md)。整个性能优化目标仍在进行。

## 最小改动与数据边界

标准化不再逐条无条件调用 `Date.now`：已有字符串形式的 `updatedAt` 直接保留，缺失时才创建当前时间的 ISO 字符串。保留字符串日期的既有规则、缺失 `createdAt` 的补全、去重、内容校验及输入隔离；每次调用重新生成缺失日期，没有跨记录或跨调用缓存默认时间。

调用范围包括缓存加载、保存/导入、添加单条记录及旧存储迁移。没有新增依赖、权限或数据库版本。

已有缓存基准直接写入缺少 `updatedAt` 的合成数据，不能充分代表经过正常保存的记录。本轮扩展为完整日期和缺失更新日期两种输入；两版共用同一测试数据和断言。

## 原生 Chrome 时间对照

macOS、Node.js 22.23.2、Headless Chrome 155.0.0.0，独立临时用户目录。两轮串行运行，顺序为基线 1、优化 1、优化 2、基线 2，不同时测试或构建。每项预热后七次取中位数；标准化完整数量、顺序、引用隔离与日期断言在计时外。计数另行运行，不影响时间采样。

| 10,000 条标准化，ms | 第一轮：基线 → 优化 | 第二轮：基线 → 优化 |
| --- | --- | --- |
| 日期完整 | 0.5 → 0.3 | 0.6 → 0.4 |
| 缺失更新日期 | 3.7 → 3.8 | 3.6 → 3.6 |

完整日期输入的标准化减少约 0.2ms；缺失更新日期时仍需逐条创建默认值，没有稳定收益。100 条中位数约 0–0.1ms，接近时钟粒度，不宣称体验改善。基准中两种输入的显式 `Date.now` 次数由 N 变为 0；缺失日期时 `new Date()` 仍读取当前时间，0 不代表不读取时钟。

完整缓存链路使用真实 IndexedDB、正文约 640 字符并带 HTML、每 1,000 条循环复用 URL。仅替代扩展消息传输，不含实际跨进程 IPC。

| 10,000 条，ms | 第一轮：基线 → 优化 | 第二轮：基线 → 优化 |
| --- | --- | --- |
| 日期完整，冷全量读取 | 64.2 → 58.6 | 64.9 → 68.8 |
| 日期完整，冷 URL 读取 | 59.2 → 62.5 | 66.2 → 61.1 |
| 日期完整，缓存更新与索引 | 1.5 → 1.3 | 1.6 → 2.4 |
| 缺失更新日期，冷全量读取 | 66.4 → 67.8 | 92.1 → 68.6 |
| 缺失更新日期，冷 URL 读取 | 63.0 → 59.4 | 70.5 → 76.6 |
| 缺失更新日期，缓存更新与索引 | 5.2 → 4.5 | 4.9 → 4.9 |

完整链路未证明稳定加速，不把标准化本身约 0.2ms 的改善换算为整体百分比。100 条冷读为 0.5–1.3ms，更新约 0.1–0.2ms，仍有亚毫秒级波动。

## 实际扩展后台内存

Chrome for Testing 153.0.8010.12 加载两版构建，使用独立临时目录、真实导入消息和 IndexedDB。1 万条中前 45 条同一来源，其余不同；保留正文及 HTML。先验收 popup 分页读取，再发送完整读取消息。连接扩展服务工作线程的 CDP target，在请求未结束时轮询 `Runtime.getHeapUsage`，请求间隔设为 5ms，实际间隔受同步处理和通信影响。

`usedSize` 是对应 isolate 的 JS 堆使用量，不是扩展独占内存或进程 RSS；其它 backing storage 字段同时保留在原始样本。指标定义见 [Chrome DevTools Protocol](https://github.com/ChromeDevTools/devtools-protocol/blob/master/pdl/js_protocol.pdl#L1493)。

| 10,000 条后台 JS 堆，十进制 MB | 第一轮：基线 → 优化 | 第二轮：基线 → 优化 |
| --- | --- | --- |
| 冷加载与操作边界的观测最大值 | 37.18 → 23.01 | 23.10 → 37.18 |
| 完整读取后强制 GC | 16.82 → 17.03 | 17.03 → 16.82 |
| 缓存失效后强制 GC | 0.72 → 0.72 | 0.72 → 0.72 |

两轮差异方向相反，没有内存改善证据。每次大数据请求取得 17–19 个轮询样本，最长间隔可超过 30ms；同步处理可能阻塞 CDP，观测最大值不能作为真实峰值上限。100 条仅取得一个轮询样本，观测最大约 1.10MB，GC 后约 0.87MB，失效后约 0.71MB。没有用采样分配量替代存活堆，也不宣称长时间无泄漏。

本次 popup 验收两种规模各预热一次，再打开七次。1 万条 `ready` 中位数为 114.3 → 114.3ms、113.9 → 131.2ms；100 条为 115.1 → 113.6ms、115.2 → 112.7ms。未证明稳定启动收益；该指标包括两个动画帧等待，后台处于唤醒状态，不是工具栏点击或服务工作线程休眠后启动。

环境、逐次样本、堆观测及界面验收：[performance-normalization-results.json](./performance-normalization-results.json)。
