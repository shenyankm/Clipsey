# 文本遍历游标与分配采样

2026-10-12；基线 `a540c5b`。延续[隐藏祖先定位验收](./performance-hidden-text.md)，以 10,000 条摘录库为主要扩展验收规模，兼顾 100 段页面。数据库记录数、页面段落数及同页恢复条数分别记录。

## 改动

隐藏祖先修复后，原文本遍历仍对隐藏子树中的每个 Text 调用过滤器。现在保留原生 `SHOW_TEXT` 遍历，在确定 `display:none` 或排除元素祖先后，将原生游标移到该祖先的最后一个后代，从子树之后继续。空元素仍由浏览器跳过，不增加逐个元素的 JavaScript 回调或样式读取。共享辅助函数只返回项目调用方实际使用的 `nextNode` 与 `filter`。

样式缓存只在一次同步遍历中有效。`visibility:hidden` 不剪除子树，子元素仍可覆盖；`display:contents`、自定义根之外的隐藏/排除祖先、Text 根、隐藏子树末尾的注释与空图片均有回归覆盖。样式读取失败保留放行与后续重试行为；暂时失败的第一次读取仍可能放行隐藏文字，本次没有改变这一兼容行为。

分配采样还发现边界映射循环每字符创建一次 `/\s/`。现在每次映射创建一个无状态正则并重复使用；Unicode 大小写扩展、空白和 UTF-16 边界语义保持原样。没有改动存储、消息协议、定位顺序、绘制、取消处理及默认每项 8ms 等待。

## Chrome 计时

Headless Chrome 155、macOS、独立临时配置。Vite 使用生产源代码，仅替代设置消息传输。预热一次、七次取中位数；基线、当前、反向当前、反向基线串行执行。计时期间没有运行分配采样、测试或构建。

普通页面包含 100/10,000 段，每段三个或五个 Text；完整恢复批次为 20 条。计时内断言文字、边界、绘制数和完整原文。另测 100/10,000 段隐藏内容及 100/10,000 个空图片容器。下表为 10,000 段场景中位数，单位 ms：

| 场景 | 第一轮：基线 → 当前 | 第二轮：基线 → 当前 |
| --- | --- | --- |
| 简单结构，尾部单次全文查询 | 23.1 → 17.2 | 22.4 → 17.1 |
| 分散节点，尾部单次全文查询 | 37.4 → 26.2 | 34.9 → 26.3 |
| 简单结构，20 条偏移定位 | 14.1 → 11.0 | 15.3 → 10.1 |
| 分散节点，20 条偏移定位 | 25.0 → 16.5 | 23.3 → 16.8 |
| 简单结构，20 条带偏移完整恢复 | 263.4 → 261.6 | 263.5 → 257.5 |
| 分散节点，20 条带偏移完整恢复 | 299.0 → 298.3 | 290.0 → 288.9 |
| 简单结构，20 条全文回退完整恢复 | 658.8 → 537.5 | 672.1 → 528.6 |
| 分散节点，20 条全文回退完整恢复 | 934.1 → 744.4 | 927.6 → 722.7 |

全文回退批次降低约 18–22%，独立偏移定位降低约 22–34%；带偏移完整恢复的变化很小，不宣称明显收益。100 段单次尾部查询约 0.1–0.3ms，完整恢复约 199–216ms，受默认逐项等待和计时波动影响，没有证明稳定的小数据批次收益。

10,000 段隐藏场景过滤回调由 30,003 次减少到 4 次，其中只检查一个隐藏 Text；可见目标与无匹配查询由约 10–11ms 降至计时粒度以内（中位数为 0ms，不能解释为零成本）。两版本都保留正确的可见偏移 7。10,000 个空图片容器的查询约 0.1–0.2ms，两版本均只读取 4 次样式。

尝试过遍历元素与文本并用 `FILTER_REJECT` 剪枝的版本，但普通页面会增加回调，也会访问空图片容器，因此未采用。正式对照只使用最终文本游标版本；两处生产源码的 SHA-256 在计时与后续验证之间保持一致。

## 分配与验证

分配采样单独运行，使用 CDP HeapProfiler、16,384 字节采样间隔，包含期间被垃圾回收的对象。每项先准备 DOM 并执行 GC，再单独采样一次查询，重复七次。记录总量与函数位置，每次核对位置汇总等于总量。正序、反序各测当前及基线。

这测量 JavaScript 分配量，不是峰值或存活堆内存；不包含 DOM 构造、原生 DOM/C++ 内存。较小场景的 0 字节代表没有采到，不能解释为没有分配。采样运行附带的计时不用于上述正式耗时对照。

下表为每次尾部查询的分配中位数，MB 使用十进制：

| 场景 | 第一轮：基线 → 当前 | 第二轮：基线 → 当前 |
| --- | --- | --- |
| 10,000 段简单结构 | 25.71 → 14.12 MB | 25.25 → 13.60 MB |
| 10,000 段分散节点 | 38.28 → 21.19 MB | 37.85 → 21.56 MB |
| 10,000 段隐藏内容 | 2.90 MB → 未采到 | 3.05 MB → 未采到 |

普通长页面采样分配量降低约 43–46%。100 段普通页面基线约 0.24–0.35 MB，当前约 0.14–0.19 MB，但相对采样间隔较小、逐次样本波动较大，不据此给小数据固定降幅。空图片容器在两版本中都未采到分配。

236 个测试、28 个文件通过 coverage（语句 59.34%、分支 54.85%、函数 61.20%、行 59.83%）；类型检查、Chrome/Edge/Firefox 构建通过。三个 content 构建产物中均确认正则位于字符循环之外，且保留跳过子树的游标逻辑。构建仍有超过 500kB 的共享 UI 代码块警告；Firefox 仍提示发布时的数据收集权限及扩展 ID 配置。

Chrome for Testing 153.0.8010.12 与 Playwright 测试包中的 Firefox 153.0 Nightly（build ID `20260722112722`，geckodriver 0.37.1）各通过 15 项原生扩展验收。Firefox 包含测试补丁，不能代替正式发行版验收。

- 实际导入 10,000 条摘录，按网址获取 20 条并用返回记录恢复；倒序、重复、清除、全文回退与相邻文字正确。
- 原生选区偏移和 64 字符上下文、外部插入、CSSOM/媒体条件变化、隐藏重复文字和隐藏选择器锚点均通过断言。
- 隐藏前缀不计入偏移；保存的可见偏移仍为 7，覆盖 `visibility:hidden` 的可见后代与 `display:contents`。
- Chrome 扩展/夹具页面异常为空；Firefox 扩展 URL 来源的非警告脚本错误为空。

选区验收在 10,000 条库流程之后保存一条测试摘录，最终测试库为 10,001 条。运行使用独立临时浏览器配置，未访问用户摘录；退出后清理配置。脚本断言验收不等同于人工逐像素检查截图。

正式计时、分配采样、源码 SHA-256 和原生结果见 [performance-text-cursor-results.json](./performance-text-cursor-results.json)。计时之后只修正了分配夹具的规模字段名（区分段落、隐藏段落与空容器），没有改变计时操作；JSON 分别保存计时阶段与最终采样阶段的夹具哈希。
