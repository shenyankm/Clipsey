# 精确计数复用与单事务分页验收

2026-10-12；基线 `efd9c1f`。以 10,000 条摘录为主、100 条为辅，承接[主键游标优化](./performance-key-cursor.md)。

## 行为与实现

普通分页现在在同一只读事务中读取精确总数和本页正文。以前两次事务之间的删除可能让 total 和 data 不一致；新增回归用例在计数时排队删除，当前页保留原快照，下一次查询看到删除后的结果。

无范围的 clips 计数按已有写入版本复用，缓存键包含数据库连接和索引名。每次在包含 clips 与 metadata 的同一事务中读取 `CLIP_REVISION_KEY`；版本一致时复用该索引的原生计数，版本变化时重新计数。首次结果只在整次事务 complete 时发布，失败或 abort 不发布。页正文每次实时读取，不在计数缓存中保存正文或主键。

缓存仅保存当前连接有效索引及主表的数字，不随摘录条数增长。缺字段的索引计数保留原生语义，不能用主表总数替代。范围查询、其他表及缺失/非字符串版本标记继续原生 count；范围分页仍共用正文的事务。写入、删除、清空与配额导致标记删除均使下一次查询重新计数；失败写入回滚后保留原有效版本。连接关闭后不跨连接复用。

`getAll` 的现有读取体提取为私有方法，供独立读取及同事务分页复用，保留范围、方向、重复键、富文本、旧字段、私有字段移除和错误处理。未增加公开 API、依赖、schema、索引、权限或近似计数。

应用内所有 clips 写入已有原子版本更新。直接通过 DevTools 原生改库并绕过该标记的写入不会使缓存失效；这与现有搜索缓存相同，调试后应重新打开管理页。版本读取失败会拒绝查询，不返回可能陈旧的数字。

## 测量方法

macOS、Node v22.23.2，真实 IndexedDB、独立临时配置、合成数据。三组环境分别为已安装的 Headless Chrome 155.0.0.0（应用版本 155.0.8059.39）、Chrome for Testing 153.0.8010.12（Headless UA 153.0.0.0）和带 Playwright 补丁的 Firefox Nightly 153.0 / geckodriver 0.37.1。不同版本独立呈现，不把一个版本的结果外推到另一个版本。

每组各四次运行：基线正序、候选正序、候选反序、基线反序；反序交换规模、索引、方向和页码。五种来源、两个方向、首页、90% 深页、越界页。每个冷查询先关闭/重建连接，并在计时外打开数据库，未预先计数；随后紧接同一页的热查询，七次取中位数。另对每次添加、删除后的第一页各测七次，写入本身及参考读取不计时。

每个样本核对全部字段、顺序、精确 total 和 totalPages；比较与断言包含在完整分页耗时中。数据正文约 640 字符、HTML 约 840 字符，含中文、缺失标题和重复索引值。所有浏览器、测试和构建串行，无 CPU/分配采样。源码在正式测量前冻结。原始十二次运行及所有样本保存在 [performance-count-cache-results.json](./performance-count-cache-results.json)。

## 冷查询、小数据与不利样本

首次查询、写入后和范围查询仍需原生 count，不宣称这些场景普遍提速。Chrome 155 正序正文降序冷首页 62.6 → 66.8ms；反序创建时间降序写入后 25.8 → 29.1ms、主表正序冷首页 9.9 → 14.2ms、正文升序删除后 66.7 → 71.1ms。复合范围正向深热页正序 31.1 → 31.8ms。原始样本全部保留，没有单独归因。

100 条，Chrome 155 热查询正序中位数范围 0.3–1.9 → 0.2–1.1ms，反序 0.3–1.7 → 0.2–1.1ms；Chrome 153 两轮多数在 0.1–1.0ms，部分增加约 0.2–0.5ms；Firefox 多数 0–1ms，反序候选有 2ms 样本。

Chrome 155 反序的小数据正文降序越界冷页，中位数出现 1.4 → 13.4ms。基线七次中前三次约 13–15ms，随后约 1.1–1.4ms；候选前四次约 13–14ms，随后约 1.1–1.3ms。两边都有暂时高延迟，但七次中位数不同；这是先测 10,000 条再清空成 100 条的顺序，尚未确定高延迟原因，不删除样本或声称小数据冷查询完全无回退。

## 检查与实际扩展

最终 324 项测试、31 个文件通过 coverage；语句 61.04%、分支 57.91%、函数 63.00%、行 61.27%。初始 14 个回归用例在修改前 4 个失败、10 个通过；最终新增 18 个用例全部通过，覆盖同快照排队删除、热缓存排队写入、索引缺字段、范围计数、版本失效、回滚、无标记、配额回退、连接替换、其他表、无效索引、abort 与计数/版本读取错误。

应用与夹具类型检查、三项脚本语法及 diff 检查通过；Chrome、Edge、Firefox 顺序构建通过。既有大共享 chunk 和 Firefox 发布配置提示保留。

Chrome for Testing 153 和同一 Firefox Nightly 加载原始生产构建，各通过 17 项实际管理页检查。第 500 页仍有精确 10,000 总数、正确 20 条完整记录及详情富文本；原生探针确认一个主键游标、20 次正文获取、0 次全量扫描、1 次版本读取和 0 次重新计数。之后继续冷/热关键词、标题排序、备份字段、后台写入/删除/清空、配额回退及脚本异常检查。使用独立配置，没有访问用户摘录。真实界面使用更短正文，此处为功能验收，未测点击到绘制耗时。
