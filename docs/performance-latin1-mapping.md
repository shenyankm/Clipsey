# Latin-1 文本边界映射的分配优化

2026-10-12；基线 `9423382`。延续[高亮恢复调度验收](./performance-highlight-scheduling.md)。主要摘录库规模为 10,000 条；本轮耗时基准另用 100/10,000 段页面，每段五个文本节点，每批恢复 20 条无偏移高亮。段落数、库记录数与同页高亮数分别计数。

## 改动与边界

文本查询已经用完整字符串进行空白规范化、小写转换与 `indexOf` 匹配；映射回原文时，旧循环还逐字符创建字符串、执行空白正则并计算小写长度。新循环对 UTF-16 单元值 0–255 使用字符码：该范围小写仍占一个单元，空白只有 9–13、32、160。每个浏览器基准都穷举 256 个字符，核对自身的小写与正则规则；单元测试通过公开查询函数检查全部字符的真实 Range 边界。

其他代码单元继续用原有正则与逐字符小写长度，保留 `İ` 的长度展开、Unicode 空白及代理对处理。全文转换、匹配、节点范围构造、已高亮跳过、定位回退和调度均保留；没有引入依赖、设置、数据库迁移或永久 DOM 索引。三个调用入口使用同一函数，不需要改接口。

## 单次尾部定位

Headless Chrome 155、macOS、独立临时配置、生产源码与真实 DOM。夹具准备后等待两帧，先预热一次，七次取中位数；单次查询计时包含正确性断言。全部计时串行，没有同时运行测试、构建、其他浏览器验收或分配采样。

执行顺序为基线正序、当前正序、当前反序、基线反序；完成两轮独立分配采样后，为整批恢复波动补跑当前反序、基线反序。反序改变规模、文本场景与绘制顺序。每次都核对完整原文、目标文本节点及开始/结束偏移。下表为 10,000 段页面尾部单次查询中位数，单位 ms：

| 文本 | 正序：基线 → 当前 | 反序：基线 → 当前 | 补测反序：基线 → 当前 |
| --- | --- | --- | --- |
| Latin-1（含 Café、Über） | 29.0 → 21.9 | 28.1 → 21.5 | 28.6 → 22.7 |
| 中文与英文混排 | 34.4 → 30.2 | 33.3 → 31.8 | 33.7 → 30.5 |
| Unicode 展开、空白与 emoji | 34.5 → 32.4 | 34.5 → 31.2 | 34.6 → 31.4 |

三次对照，Latin-1 尾部定位减少约 21–24%，中文混排约 5–12%，混合 Unicode 约 6–10%。100 段尾部查询中位数为 0.2–0.4ms，接近计时粒度，不宣称小页面提升倍数。找不到文字时不会进入映射循环，没有预期算法收益；完整头部、中部、尾部与缺失查询样本均保留在原始数据中。

## 独立分配采样

另起四个浏览器进程，顺序为基线正序、当前正序、当前反序、基线反序。每种夹具的 DOM 准备与 GC 在采样前完成；仅包住一次尾部查询与边界断言。使用 CDP HeapProfiler，采样间隔 16,384 字节，并计入期间被大小 GC 回收的对象；每项七次取中位数，逐个样本核对分配位置之和等于总量。

下表为 10,000 段尾部查询的 JS 采样分配量，MB 按 1,000,000 字节计算：

| 文本 | 正序：基线 → 当前 | 反序：基线 → 当前 |
| --- | --- | --- |
| Latin-1（含 Café、Über） | 25.53 → 14.86 | 25.94 → 14.87 |
| 中文与英文混排 | 31.41 → 25.25 | 31.72 → 24.96 |
| Unicode 展开、空白与 emoji | 30.18 → 24.70 | 29.73 → 24.51 |

Latin-1 总量减少约 42–43%，中文混排约 20–21%，混合 Unicode 约 18%。首轮 Latin-1 的映射函数位置中位数约 10.98MB，当前正序中位数为 0（其中一个样本仍记录约 16.4kB），反序未记录到该位置；不能据此断言该函数绝对零分配。100 段也观察到较小的采样总量，但字节数受采样粒度影响，不作为硬阈值。

这些是临时 JS 分配的采样估计，包含已回收对象；不是峰值堆、常驻堆、原生 DOM 内存或泄漏检测。采样进程中先跑的耗时数据不参与上面的耗时对照。整页拼接、规范化及 DOM 遍历仍有分配成本。

## 整批全文回退

实际 HighlightEngine 恢复 20 条无偏移载荷，使用生产绘制与默认调度，仅设置传输使用空响应。DOM 构造及两帧准备不计时；完整恢复包含 DOM 就绪/空闲等待。每次确认 20 个目标与原文正确，清除后完整原文不变。10,000 段的完整恢复中位数，单位 ms：

| 文本 | 正序：基线 → 当前 | 反序：基线 → 当前 | 补测反序：基线 → 当前 |
| --- | --- | --- | --- |
| Latin-1（含 Café、Über） | 712.7 → 660.4 | 579.3 → 597.4 | 559.9 → 505.2 |
| 中文与英文混排 | 804.9 → 765.3 | 640.6 → 693.1 | 623.4 → 629.5 |
| Unicode 展开、空白与 emoji | 806.0 → 811.7 | 635.9 → 713.1 | 641.2 → 610.3 |

整批结果没有稳定收益：第一轮部分更快，第二轮分别慢约 3%、8%、12%，补测为 Latin-1 快约 10%、中文混排慢约 1%、混合 Unicode 快约 5%。不能把单次查询的收益套用到整批恢复；未证明这些差值的具体原因。保留此改动的依据是重复确认的尾部定位与临时分配收益。

100 段整批恢复为 6.5–10.0ms，基线为 7.0–10.3ms，也不支持稳定的倍数改善。没有更改调度策略或增加缓存来掩盖这些波动；较大全文回退批次仍是待评估的成本。

## 完整回归与实际扩展

256 个测试、28 个文件通过 coverage：语句 59.46%、分支 55.27%、函数 61.35%、行 59.95%。类型检查、Chrome/Edge/Firefox 顺序构建、两份原生脚本语法及 diff 检查通过；三个 content 构建产物都核对了字符码路径及非 Latin-1 小写回退。共享 UI >500kB 及 Firefox 发布配置警告仍存在。

Chrome for Testing 153.0.8010.12 与带 Playwright 补丁的 Firefox 153.0 Nightly（build ID 20260722112722，geckodriver 0.37.1）各通过 18 项实际构建验收。实际 10,000 条摘录库供给页面的 20 条记录，倒序、重复、全文回退及清除正确；另以 1,000 段、1,000 条合成载荷检查整批恢复与页面定时器，两浏览器定时器均在第 1 条绘制后执行。这批合成载荷没有写入库。

新增原生用例先放置全部 256 个 Latin-1 代码单元及中文、希腊文、大小写展开、代理对和 Unicode 空白，再查询 `i̇stanbul 中文🙂 café`。两浏览器都在正确目标恢复完整原文 `İSTANBUL 　中文🙂 Café`，清除后原文不变。外部插入、CSSOM/媒体条件隐藏前置内容、隐藏重复目标、原生选区与可见性覆盖检查继续通过。

隐藏选区检查额外写入一条记录，最终 10,001 条已断言。Chrome 页面/扩展异常为空，Firefox 扩展 URL 来源非警告错误为空；临时浏览器配置退出后清理，未访问用户摘录。Chrome 截图由脚本生成，没有人工视觉检查。

环境、逐次样本、分配位置、源码/构建 SHA-256 与完整原生结果见 [performance-latin1-mapping-results.json](./performance-latin1-mapping-results.json)。
