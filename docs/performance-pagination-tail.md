# 冷深页的近末端读取验收

后续[分页端点的临时分配验收](./performance-page-endpoints.md)减少页内中间边界采集；本报告保留此前阶段结果。

2026-10-12；基线 `e85ba29`，承接[新深页的有界游标边界](./performance-page-anchors.md)。以 10,000 条为主、100 条为辅，另验证 10,001 与 20,000 条，避免只在主规模内受益。全部 24 轮样本、初始原型、红测试、源码与构建 SHA-256、界面结果见[原始数据](./performance-pagination-tail-results.json)。

Chrome 155 两轮的 10,000 条冷深页，创建时间排序约 53–61ms → 29–38ms，正文排序约 133–134ms → 74–80ms。Firefox 正文约 6–7ms → 3–4ms，但个别创建时间场景为 2 → 3ms；范围和较早页面的完整取舍见下表。

## 实现与边界

原路径从请求方向的起点推进 offset。深整数页现在先取得同一只读事务的精确 total：若页在范围外，直接返回空；若没有可用的已缓存边界且 total − 页末位置 − 1 小于 offset，就从相反方向推进这个距离，读取本页主键后反转，再获取新鲜正文。例：10,000 条、offset 9,000、每页 20 条，定位距离从 9,000 缩到 980。部分末页按精确 total 截断，最后一页可以不调用 advance。

沿用 offset >= 256、uint32 范围、整数页量 1–100、next/prev（含 asc/desc）的主键游标资格；浅页、unique、特殊参数仍用原路径。这条定位适用于范围及其他表，不依赖字符串索引键或主键。索引 count 保留缺字段、混合主键和重复键的原生语义；不使用主表总数替代索引总数，不使用旧版本数字定位。

已缓存的同页或可用边界仍优先，保护前一阶段收益。末端读取采集的两个边界恢复为请求方向下的逻辑位置，供下一页定位；缓存资格、16 页/256 KiB 字段预算、失败及写入后的失效规则保持原有约束。结果只暂存本页最多 100 个主键，不扫描全量主键，不增加持久化数据、schema、依赖、权限或公开 API。正文索引边界仍可能包含正文字符串，字段预算不是实际堆上限。

深页等待精确总数可能增加早页开销；首次原生计数仍占主要成本，范围仍逐次计数。初始原型分段计时包含版本读取、计数、定位和正文获取；正式比较只引用完整生产方法，不把各阶段中位数相加，也不拿缓存复访当冷查询。

## 冷深页完整方法

每次样本前关闭/重开连接，计时外打开数据库但不预热 count。目标页 offset 为命中总数约 90% 的整页位置；范围以命中数定位。每格基线生产 → 最终生产，单位 ms，七次中位数；两种执行顺序均保留，计时包括精确总数、页数、顺序和全部字段断言。

## 原计数、复访和邻页对照

独立重跑原 `pagination-count` 的第一/深/越界、冷/热、插入/删除及范围矩阵八轮，并重跑 `page-anchors` 五来源双方向、早页、相邻/远跳和 20,000 条重复值矩阵八轮。所有精确字段断言通过；这些完整样本和不利中位数均在原始数据。缓存邻页仍使用原来的联合定位，没有把末端读取替代所有边界选择。100 条保持浅页路径，不能因个别 0–1ms 量化样本宣称普遍收益。
