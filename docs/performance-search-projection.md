# 搜索小记录扫描实验：暂不接入持久化表

2026-10-12；生产基线 `6e2f954`。以 10,000 条摘录为主要验收规模，兼顾 100 条。延续[搜索分页优化](./performance-search.md)，本轮生产代码未变更。

## 结论与代价

在合成富文本数据上，扫描只包含 ID、标题、正文、网址与时间的记录，然后取回本页完整摘录，确实减少了搜索耗时。两轮 10,000 条查询降低约 19%–52%，绝对差值约 10–29ms。但新增表的批量写入增加约 15%–32%，还会重复持久化正文等字段。

暂不增加生产数据库表。当前查询约 49–59ms，输入已由 `ClipManager.vue` 合并 180ms；`useClipSearch` 也会丢弃旧请求结果。为这一收益引入升级回填、所有写入路径的原子同步、失败恢复与额外空间，现阶段成本偏高。180ms 只是源码中的输入延迟，未测成端到端体验。下一步优先评估复用已有缓存；这只是后续方向，尚未实施或验收。

## 隔离实验

`tests/performance/search-projection.ts` 在临时浏览器数据库创建无索引的实验表，保留生产版本号与配置文件。实验替换事务包装，为摘录事务加入该表；批量/单条 `put`、删除、清空在同一事务镜像操作。只把搜索的主表 `getAll` 重定向到实验表，分页最终的 `get(id)` 仍从完整摘录表读取。关闭夹具时恢复包装与配置。

两个模式调用相同的生产搜索服务、筛选、堆排序和分页。查询返回记录逐字段比较，包括 HTML；检查总数、顺序、单次扫描不超过 256 条。另核对实验记录与主表投影一致，验证更新可被搜索、删除无残留、清空两表。没有把这一有限检查称为完整的迁移、回滚或跨浏览器验收。

数据与原搜索夹具一致：每条约 640 字符正文、约 840 字符 HTML，重复标题、部分缺失标题、重复时间及网址，含中文与大小写。更长正文、更大 HTML、真实用户数据和其他大小分布尚未覆盖；不能把该相对收益套用到所有摘录。

## 两轮独立测量

macOS、Node.js 22.23.2、Headless Chrome 155、独立临时用户目录。两次进程串行运行，第二次反转规模、模式与查询顺序；每项预热一次、七次采样取中位数，不同时执行测试、构建或 CPU 采样。查询计时包含结果断言；准备数据与写入一致性核对不计入对应计时。没有强制 GC；阶段间资源影响未单独归因。

10,000 条，单位 ms；“完整 → 小记录”均包括本页完整记录取回：

| 查询及排序 | 正序 | 反序 |
| --- | --- | --- |
| 正文 `NEEDLE`，时间倒序，深页 | 59.2 → 34.0 | 54.5 → 32.7 |
| 网址 `/article/1`，网址正序 | 55.8 → 26.6 | 49.3 → 28.5 |
| 全字段 `测试`，正文正序，第 2 页 | 48.9 → 30.0 | 50.9 → 31.0 |
| 正文 `absent`，无结果 | 49.0 → 30.0 | 51.2 → 41.6 |
| 全字段 `needle`，标题正序，第 2 页 | 50.0 → 31.2 | 49.8 → 35.6 |
| 空查询，标题倒序，深页 | 51.1 → 32.0 | 52.8 → 34.7 |

100 条正序：完整记录 0.4–0.9ms、小记录 0.3–0.8ms。反序：完整记录 0.4–0.7ms，小记录四项 0.3–0.6ms，但两项标题查询均为 6.0ms。保留这些不利样本，没有据此断言小数据必然变快，也未证实其原因。

批量写入使用现有 `bulkPut`，每批 1,000 条；两个模式均清空后写入，清空不计时。包含事务完成、派生网址键和现有索引维护：

| 规模 | 正序：完整 → 镜像写入 | 反序：完整 → 镜像写入 |
| --- | --- | --- |
| 100 | 6.5 → 8.7 | 10.1 → 13.4 |
| 10,000 | 1,488.1 → 1,710.7 | 1,405.6 → 1,857.0 |

未测单条保存的耗时、物理磁盘增量、峰值内存或分配量，不把批量差值换算为用户每次保存的延迟。

## Profile 与验证边界

先单独采样原搜索夹具：约 3.596 秒、2,403 个 CPU 样本，空闲约 2.391 秒、`program` 约 0.425 秒；比较字符串约 0.054 秒。采样包含准备写入与参考排序，没有隔离一次查询。空闲占比提示继续检查原生操作与等待，但无法据此把全部空闲归因为 IndexedDB 克隆或某一项 I/O。[原始 CPU profile](./performance-search-projection.cpuprofile)与其计时单独保存，未混入上表。

两轮夹具均完成且通过断言。生产 app 类型检查、夹具独立类型检查、脚本语法、错误组合参数保护与 diff 检查通过。开发夹具时先修正了不存在的更新接口，再修正单条 CRUD 绕过 manager façade 的事务范围问题；失败运行没有计入结果。
