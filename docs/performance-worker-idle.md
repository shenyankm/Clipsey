# 后台自然休眠与唤醒验收

日期：2026-10-11；源码基准 `bdd705f`（生产实现仍为 `e2d5839`）。主要规模为 10,000 条，另测 100 条。本轮增加测量脚本与证据，没有修改生产实现。

## 方法与正确性

使用实际 Chrome for Testing 153.0.8010.12、构建后的扩展、独立临时用户目录和合成数据。只连接设置页面的 CDP，不连接后台调试器、不强制终止后台。通过 Chrome 的 `/json/list` 每秒观察一次目标：必须先看到本扩展的 service worker 消失，再发送请求，并断言回复后出现的新 target ID 与原 ID 不同。

Chrome 官方说明：无活动时后台通常会被终止，收到新事件可再次唤醒，内存变量不会跨终止保存。因此不能仅清空应用缓存就称为后台休眠测试。[生命周期说明](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)

每种规模先导入并预热，然后执行七次以下流程，串行运行：

1. 等待后台自然终止，最多等待 60 秒；未观察到终止就失败。
2. 请求当前网址的最新 20 条分页，记录首个消息往返耗时，验证后台 target 已更换。
3. 再请求同一分页，记录后台已唤醒时的耗时。
4. 请求全部摘录，再重复请求一次，分别记录全量缓存未命中、命中时的耗时。

每个响应都在计时外验证数量、全部 ID 顺序和私有字段未泄漏。两种数据库均有 45 条属于查询网址；分页固定返回 `clip-44` 至 `clip-25`。全量响应覆盖全部 100 / 10,000 条，按日期倒序，禁止出现 `__clipseyUrlKey`。

## 结果

14 次自然终止与唤醒均通过。每次观察到的空闲时长约 30.1 秒；这是 1 秒轮询下的观测值，不能当作精确终止时刻。每项七次取中位数，单位 ms：

| 数据规模 | 唤醒后的首个分页请求 | 再次分页 | 全量缓存未命中 | 全量缓存命中 |
| --- | --- | --- | --- | --- |
| 100 | 5.8 | 1.2 | 1.9 | 0.6 |
| 10,000 | 5.1 | 1.1 | 133.0 | 50.4 |

分页唤醒没有随这两种数据库规模出现明显增长；这是当前版本的观测，不是旧版本对照，也不支持宣称新增优化比例。1 万条全量响应的成本较大，后续应进一步区分全量缓存处理与消息序列化/传输成本。

计时包含后台处理及 `chrome.runtime.sendMessage` 往返，包含大响应的序列化、传输和接收，不能等同于此前仅测缓存方法的耗时。正文约 640 字符并带同量富文本；合成数据的体积会影响全量结果。

“全量缓存未命中”发生在两次分页之后，此时后台和数据库连接已经唤醒，但尚未读取全量缓存；它不是休眠后的首个全量请求。计时不包含 popup 渲染、工具栏点击、浏览器进程启动、数据库升级或磁盘缓存清空。

## 脚本与检查

[worker-idle-performance.mjs](../scripts/worker-idle-performance.mjs)不依赖 Playwright，复用现有原生 Chrome/CDP 测量方式。明确匹配本扩展的后台 URL，避免将浏览器其他扩展的 target 当成本项目后台。

```sh
CHROME_PATH='/path/to/Chrome for Testing' node scripts/worker-idle-performance.mjs
```

可用 `EXTENSION_PATH` 指定已构建的 service-worker 扩展；`--reverse` 反转规模顺序。正式本轮只测了默认顺序，未宣称反转对照。脚本打印各次进度，结束时将 JSON 写入独立结果目录，并清理浏览器进程和临时用户目录。

脚本语法检查通过。另行通过四个失败清理断言：浏览器可执行文件不存在、浏览器提前正常退出、浏览器被信号终止、扩展目录不存在。均以失败退出，不遗留浏览器用户目录。请求与计时路径在本轮测量期间未变；测量后补充了这些启动失败清理保护并单独检查。

原始逐次样本、target ID、生产产物 SHA-256 和检查范围：[performance-worker-idle-results.json](./performance-worker-idle-results.json)。生产源码没有变化，本轮未重跑全量单元测试、类型检查或三浏览器构建；对应生产实现的检查见[缓存验收](./performance-cache-snapshot.md)。

尚未测量休眠后的首个全量请求、完整 popup 唤醒渲染、取消休眠时的竞态、浏览器进程重启、Edge/Firefox 运行时、峰值内存、低端硬件、真实用户数据或远端 CI。整个性能目标仍在进行。
