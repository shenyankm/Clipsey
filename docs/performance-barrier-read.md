# 接受文本时跳过隐藏屏障读取：未采用

2026-10-12；基线 `275fc2f`。延续[可见父元素排除检查优化](./performance-visible-parent.md)。主要摘录库规模为 10,000 条，兼顾小数据；本轮另测 100/10,000 段页面与每批 20 条无偏移高亮。实际库与消息链路的原生验收见上一轮报告，本轮未重跑。

## 改动与正确性

`acceptNode` 在确认可见后仍从 `barriers` 读取屏障，再返回接受；`nextNode` 接受节点时直接返回，只有拒绝节点才使用屏障跳过隐藏子树。候选让可见节点先返回接受，屏障读取留在拒绝分支。每次过滤开头仍把 `lastBarrier` 清为 null，样式读取失败的原有接受路径也保留。

未采用候选：虽然有读取次数减少的直接证据，两轮没有稳定的整体收益，反序部分布局更慢，不能把减少一次读取直接等同于实际路径变快。原因未单独归因；也没有根据这些数据证明候选必然变慢。候选与计数测试已移出工作树，完整源码保存到原始报告，生产实现继续使用 `275fc2f`。

不依赖可见元素的屏障值一定为空，只依赖调用方根本不消费接受节点的屏障。拒绝节点仍设置屏障，隐藏子树跳过、visibility 覆盖、自定义根外隐藏祖先、排除标签和样式失败重试继续使用原逻辑。没有新增缓存、接口、选项、依赖、权限或数据库变更。

探索用回归测试先访问父元素的首个文本，再直接过滤同父第二个文本；统计这一次过滤的 WeakMap 读取，断言结果仍为接受。原实现读两次，测试失败；候选读一次，测试通过。spy 在断言前恢复，未用于浏览器计时。计数证据只描述该过滤阶段，不等同于全文查询提速一倍。

## 独立耗时
