# Popup 启动与内存验收

日期：2026-10-11；基线：`aa12a80`。延续[长页面优化](./performance-highlights.md)，主要数据规模仍为 10,000 条，兼顾 100 条。

## 本轮改动与取舍

Popup 初始进入加载状态，确认没有摘录后才挂载空状态组件。避免在已有摘录的页面先渲染“暂无摘录”，再移除这套 DOM、样式与组件实例；后续刷新已有列表时仍保留列表。加载失败时保留错误提示和原有空状态。

仅改两处模板/初始状态，不改变查询、分页或富文本净化。最终静态 JS 为 697,316 bytes，基线为 697,298 bytes，基本不变。

曾尝试按实际用到的 Typography 子组件注册并删除未使用的 Tooltip 注册：静态依赖只减少 1,237 bytes，两轮启动对照未证明稳定收益，已撤回。没有更换 UI 库、增加依赖或拆分更多加载层。

## 实际扩展测量

macOS、Node.js 22.23.2、Headless Chrome for Testing 153.0.8010.12；加载构建后的扩展，用实际设置读取、tabs 查询、扩展消息和 IndexedDB。独立临时用户目录与合成摘录，不访问用户数据。网页标签保持激活，popup 作为后台扩展页打开。尺寸为 450×640px，与源码规定的 450px 页面宽度一致；较早的 420px 试验仅用于探索。

每种规模预热一次，再新建 popup 七次。页面导航起点为零，记录标题区域、20 条列表及加载状态结束，再等待两个动画帧作为 `ready`。这不是点击浏览器工具栏到弹窗可见的操作系统级耗时，也不是服务工作线程休眠后的冷启动。第一轮先基线，第二轮先优化；串行运行，不与测试、构建或其它验收同时运行。

摘录正文约 640 字符并带富文本；45 条属于当前页面，其余属于不同 URL。逐次断言 URL、最新记录顺序、20 条记录及富文本标记正确。

| 场景，中位数 ms | 第一轮：基线 → 优化 | 第二轮：基线 → 优化 |
| --- | --- | --- |
| 100 条，列表完成 | 111.4 → 102.4 | 101.3 → 90.5 |
| 100 条，两个动画帧后 | 125.9 → 110.7 | 111.6 → 106.6 |
| 10,000 条，列表完成 | 110.3 → 93.2 | 99.5 → 94.7 |
| 10,000 条，两个动画帧后 | 121.3 → 108.8 | 110.4 → 109.8 |

耗时有波动，不能把上述差值全部归因于两行改动，不宣称稳定百分比收益。确定的行为变化是：有摘录时，基线每个规模的 14 次采样都在结果前挂载空状态，优化后均未挂载。小数据未观察到稳定退化。

## 分开测量内存

每次启动计时结束后强制 GC，再读取渲染进程的 `JSHeapUsedSize`；避免把关闭页面的未回收对象误判为持续占用。该指标包含同一渲染进程中仍存活的扩展页面，不是 popup 独占内存或进程 RSS。两种规模的优化中位数约 14.69MB，基线约 14.74MB；这是跳过空状态后的很小差异。

后台另外连接 service worker 的 CDP target，使用 `Runtime.getHeapUsage`，在操作结束及强制 GC 后分别记录。最终版本两轮的 10,000 条场景，GC 后 V8 堆占用如下（十进制 MB）：

| 操作后 | 约占用 |
| --- | --- |
| 导入结束 | 0.71MB |
| popup 分页读取结束 | 0.71MB |
| 主动全量读取并建立缓存 | 17.52MB |
| 删除一条，缓存失效 | 0.72MB |

分页不会永久保留全库记录，全量缓存失效后可回收。以上是操作边界的堆快照；没有连续采样，不能当作峰值内存上限或长时间无泄漏的证明。单次 full-cache 的标准化和复制已在[后续优化](./performance-cache.md)中测量并减少。

原始逐次样本、环境、后台快照及验收：[performance-popup-results.json](./performance-popup-results.json)。

## 验证与复跑

- 181 个测试、类型检查和 Chrome/Edge/Firefox 构建通过。
- 实际扩展增加三个受控响应验收：有摘录、空结果、失败。只延后真实分页回复，验证等待时没有空状态且有加载指示；放行后正确显示摘录、空状态或错误消息。截图检查了加载和完成状态。
- 既有实际扩展 17 项管理页/备份/搜索/同步验收重新通过；脚本启动失败时临时用户目录清理验证通过。
- 构建仍保留共享 UI 大 chunk 与 Firefox 发布配置警告，没有新增权限、数据库版本或依赖。

脚本需要独立可用的 Playwright 与支持加载扩展的 Chrome for Testing；它们只用于验收，没有加入应用依赖。`PLAYWRIGHT_MODULE` 可指定已有 Playwright 模块文件路径，否则从环境解析 `playwright`。`CHROME_PATH` 指向浏览器可执行文件：

```sh
CHROME_PATH='/path/to/Chrome for Testing' node scripts/popup-performance.mjs
EXTENSION_PATH='/path/to/baseline-build' CHROME_PATH='/path/to/Chrome for Testing' node scripts/popup-performance.mjs
```

基线应先在临时 checkout 构建 `aa12a80` 并保存产物；脚本不负责切换分支。所有用户目录在结束或启动失败后清理。可设置 `PROFILE` 保存一次原生 CPU profile。

后台缓存的冷读取与采样分配量已完成[后续对照](./performance-cache.md)，连续峰值仍待测量；Edge/Firefox 运行时、低端硬件、服务工作线程休眠后启动及远端 CI 尚未验收。整个性能优化目标仍在进行。
